## Original findings (resolved; retained as reproduction evidence)

1. **P1 — Stop does not close a quiet subscription.** `web/src/features/graphql/fetcher.ts:78` returns an async generator whose pending `next()` continuously polls until an event is yielded or `context.current()` becomes false (`:88`, `:125`). GraphiQL 5 cancels async iterables by calling `value[Symbol.asyncIterator]().return()` (`@graphiql/react/dist/stores/execution.js`; upstream source lines 323–329). Async-generator `return()` queues behind the pending `next()`; it cannot interrupt this loop. Trigger: start a subscription that emits no `next`/terminal event, then press Stop while staying on the same request. The UI drops its subscription handle, but polling continues and the Rust session is not closed, consuming connection/admission quota until another lifecycle transition or server completion. The `finally` close at `fetcher.ts:127` does not run because the generator never yields/returns. Independent `/tmp/graphql-ui-review.test.ts` asserts that after cancellation the iterator remains pending, the session remains registered, and no `/close` occurs across three polls/1.1 seconds; invalidating the scope then closes it. Fix needs an explicit immediate cancellation path rather than relying on generator `return()` reaching `finally`.

2. **P1 — Rapid request switching can erase the outgoing canonical query.** `web/src/features/graphql/GraphQLWorkbench.tsx:128` applies editor patches through `latest.current.request` with no mounted/scope/generation check; `:273` wires it to GraphiQL's query callback. Upstream `OperationEditor` delays this callback by 100 ms, and its debounce timer survives model/editor disposal. Trigger reproduced in an independent browser fixture: request A starts with `query First {value}\nquery Second {value}`; type ` X` at the end, immediately click request B, then save the workspace. Saved JSON becomes A `protocol.document == ""`, while B remains `query Other {value}`. A disposed editor's delayed callback runs during the transition; the application accepts its empty string. The scope guards in `getContext()` protect execution results, not these editor callbacks. Preserve edits immediately/flush before disposal and fence delayed editor callbacks by their originating scope. A stale-callback guard alone should also be checked for loss of the user's last 100 ms of edits.

3. **P2 — Saved operation selection is not restored.** `web/src/features/graphql/GraphQLWorkbench.tsx:260` initializes query/variables and persists `onEditOperationName`, but never supplies saved `gql.operation_name` to GraphiQL. GraphiQL's provider supports the `operationName` prop and defaults it to `null`; its operation discovery selects the first operation. Browser proof: saved two-operation document with `operation_name: "Second"` opens with tab/operation `First`. `fetcher.ts:33` then replaces the saved selection with GraphiQL's parameters, so ordinary execution uses the wrong saved operation after reopening. Restore selection in the mature editor and verify selection changes still work.

4. **P2 — Saved SDL/introspection sources do not drive the schema browser.** `web/src/features/graphql/GraphQLWorkbench.tsx:120` derives schema solely from transient component `schema` state, which is only assigned after live dedicated introspection (`:175`). There is no lookup of the request's `specification_id` or persisted `graphql-sdl` / `graphql-introspection` source. Trigger: reopen a saved request with a valid saved schema while live introspection is unavailable/disabled. GraphiQL attempts automatic network introspection and has no schema/docs despite the canonical source being retained. Independent browser fixture supplies a saved `graphql-sdl` `type Query {value:Int}`; startup still posts `IntrospectionQuery` to `/api/execute` and reports its disabled-introspection error. This blocks the specified saved-schema source capability and offline/schema-disabled use. Resolve the owner/workspace-bound reference and build with mature `buildSchema` / `buildClientSchema`, retaining error handling and lifecycle guards.

5. **P2 — The main Send action bypasses the GraphQL UI result/transport path.** `web/src/features/workbench/useWorkbenchController.ts:60` dispatches only SSE/WebSocket through sessions; GraphQL goes through `requests.send` (`/api/execute`). `web/src/features/requests/RequestEditor.tsx:191` keeps this button, but its GraphQL response branch (`:431`) renders only `GraphQLWorkbench`; that component reads its private `last` state (`GraphQLWorkbench.tsx:188`), not `state.response` / `requestError` from `useRequests`. Trigger: press the main Send button for a GraphQL query/mutation; response or backend errors are stored in a state the visible GraphQL pane never consumes. For subscriptions this action also selects the finite endpoint and cannot connect. The window Ctrl/Cmd+Enter shortcut uses the same dispatch (`useWorkbenchController.ts:186`); GraphiQL has its own shortcut, so verify keyboard event routing while integrating a single operation-aware execution path. This is established by source tracing; the independent fixture uses an older main-bundle header while the root changes that layout, so no current-label/runtime claim is made for this finding.

## Reviewed protections and interchange behavior

- GraphiQL/GraphQL are loaded through a React lazy module, with official `graphiql/setup-workers/vite` and Vite ES workers. Existing dist has editor, JSON and GraphQL workers plus local editor/CSS/font chunks. Independent browser loaded these from its own loopback origin. Existing server embedding copies the complete dist tree; this is asset/layout evidence, not a fresh native/package/platform build.
- Custom fetcher targets same-origin Rust `/api/execute` / owner-bound session APIs, never the saved external target directly. It uses mature `parse` / `getOperationAST`, preserves HTTP response/status in the inspector, requires GraphQL `data` or `errors`, passes GraphQL data/errors through, and does not turn nested target HTTP 401 into an outer owner-auth 401.
- Execution and dedicated introspection contexts check mounted/account/workspace/request/environment plus scope-generation state before applying responses/local changes. Subscription preparation adds the ID and, when scope is already invalidated, enters `finally` and closes it. Known sessions are closed on scope cleanup. The stop defect and unguarded editor callback path remain exceptions described above.
- GraphiQL storage is a no-op Storage implementation and headers/history persistence is disabled. Canonical document/raw variable draft updates use workspace state; invalid raw variable syntax is retained. Ordinary browser typing preserved text and focus. A suspected inline-callback editor-reset issue was refuted by both browser typing and inspection of upstream effect dependencies; it is not a finding.
- Introspection source saving appends/deduplicates by kind/source and preserves unrelated specification references; schema-build exceptions produce a message rather than crashing.
- Postman GraphQL import preserves query, raw variables draft, canonical parsed object and scripts. Export writes official 2.1 GraphQL body shape and validates the final collection against bundled official schema. The export guard explicitly rejects unsupported subscriptions, explicit operation selection, connection parameters, subscription URLs and formats without a GraphQL adapter. No additional confirmed interchange defect was found in this scope.
