# SSE and WebSocket protocol session implementation brief

Read docs/specs/protocol-sessions.md and tasks/implementation/plan.md. This follows the verified script/scoped-variable extension. Work only in the active implementation worktree after the controller provides its commit as BASE. One implementation worker at a time; do not start your own reviewer or publish changes.

Own Rust core, a new modular protocols crate, server protocol/session APIs and relevant tests. Add root workspace/Cargo dependency entries as needed and tell root immediately about the stable TS/API shape; root owns all frontend code, desktop capability JSON, distribution and documentation aggregation. Avoid changing the public HTTP contract incompatibly. Existing RequestSpec JSON without protocol must still load; session events have typed metadata and explicit monotonic retention cursors.

Reuse mature crates for SSE parsing, WebSocket handshakes/framing, URL/header/TLS handling and cancellation. Prefer an existing reqwest WebSocket upgrade adapter if it can preserve the shared client's DNS-pinning/network/TLS settings and enforce framing caps; otherwise use a checked socket + mature TLS/handshake adapter. Do not implement protocol framing, SSE grammar, WebSocket crypto or custom JSON parsing. Extract shared network validation/client construction instead of duplicating HTTP SSRF policy. No unchecked connect_async DNS path, proxy bypass of policy or browser-direct network execution.

Public session operations must work through both hosted HTTP and Tauri in-process JSON IPC; no local native TCP server. Scope sessions to authenticated owner and existing workspace/request; reads/sends/closes must verify ownership. Bound session admission, commands, events, bytes and lifetimes, with explicit dropped-event cursor gaps. Validate message sizes before Base64 decoding/allocating. Persistent workspace state and session state remain separate; no raw session messages in shared sync/history.

Run project/collection/request pre scripts with the existing isolated worker, retaining known private values for summary/error masking; reject post-response scripts for live protocols explicitly until a per-event contract is implemented. Clean up sessions on workspace deletion and shutdown. Address admission/deletion races: register connecting session before a final workspace/request ownership recheck, so deletion can cancel it; recheck and abort if it vanished while preparing. Connection state changes and task errors must never falsely report open/success.

Real loopback fixture tests are mandatory: SSE split chunks/multiline/id/retry/unterminated oversized buffer; WebSocket echo text/binary/ping/close; cancellation while connecting/reading; retention gap/order; private hosted network deny/native allow; owner isolation; deleted-workspace cleanup; old JSON compatibility; native/no-default compilation. Tell root which exact checks ran and output, and which limits remain. Do not repeat tests without an amended change/failure/concern. No dummy capability/UI or broad parity claims.

Before returning, write tasks/implementation/protocol-report.md with changes, interface, actual verification and unimplemented limits. Leave changes uncommitted for combined frontend review/commit, unless root later instructs otherwise. Do not modify user branding or existing untracked draft artifacts.
