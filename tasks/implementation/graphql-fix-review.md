The existing new WebSocket fixture passed all six alias × next/error/complete combinations, asserting no typed GraphQL event and the existing unknown-subscription error path. Canonical next/error/complete/cancel cases also passed freshly. This deliberately closes the connection as a protocol error for noncanonical IDs; it does not silently ignore them. The mature actor/parser remains intact.

2. **GraphQL-JS introspection interoperability resolved with an explicit grammar limit.** The retained 19,667-byte fixture contains `DIRECTIVE_DEFINITION` in `@deprecated.locations`. The vendored Cynic source adds exactly that enum value in `src/schema.graphql:105`, `src/query.rs:196` and `src/schema/sdl.rs:463`. A complete source-tree comparison against downloaded Cynic 3.14.0 confirms no other source differences: the portable query, mature model conversion and SDL writer remain upstream. The exact response now converts, and the real local HTTP fixture passed introspection → workspace save → schema reload with the original response preserved byte-for-byte. Custom directives on that location are explicitly rejected before SDL generation (`crates/core/src/graphql.rs:332`), because the selected SDL parser lacks that grammar. Direct SDL imports report the same specific limit at the mature parser's failing token (`:42`); a valid ordinary field named `DIRECTIVE_DEFINITION` stays accepted. Existing regressions for both limitations passed freshly. This is bounded interoperability with the actual fixture, not a claim of complete newer-spec grammar support.

## Addressed findings

1. **Introspection operation roots remain preserved.** `crates/core/src/graphql.rs:346` checks Cynic's generated SDL through the bounded mature parser. If Cynic omitted the schema declaration, `explicit_schema_roots` (`:57`) constructs one through the public Cynic AST writer/printer, using only the introspected query/mutation/subscription map. Null mutation/subscription roots are absent from that declaration even when ordinary objects named `Mutation` or `Subscription` remain in the SDL. When Cynic already emits a declaration for nonconventional root names, the mature formatter supplies the introspected map. Original introspection source remains unchanged. The existing regression compares parsed roots to Cynic's introspection schema and checks both ordinary object types remain present; it passed freshly after round2.

2. **Recursive query/schema parsing retains its pre-parse quota.** `check_graphql_structure` (`crates/core/src/graphql.rs:18`) iterates Apollo 0.8.6 public lexer tokens, rejecting nesting above 32 or lexer token-limit errors at 1,000,000 tokens. Inspection of Apollo's installed lexer confirms an iterative scanner and an error when the token quota is exceeded; strings/comments/block strings remain mature-library tokens. Every production `parse_query`/`parse_schema` call is preceded by this guard. `bounded_schema` checks 5 MiB before lexing/parsing; selected executable documents check 256 KiB. This covers nested types and default-value literals as well as selection sets. Importantly, generated introspection SDL goes through `bounded_schema` on its **first** parse (`:347`), before schema-definition inspection, and again after root insertion (`:361`). Valid saved SDL is returned byte-for-byte. Existing isolated defensive regressions freshly rejected 4,000 levels for SDL list types/defaults and query variable types/defaults; quoted delimiters remained accepted. The existing server save regression freshly rejected deep SDL and then successfully used the API.

3. **Known credentials in `subscription_url` are captured across pre-script changes.** `crates/server/src/privacy.rs:212` visits both shared URL and optional subscription URL, before scripts, after successful scripts, and after resolution through the calls in `crates/server/src/execution.rs:277`, `:306`, and `:344`. Raw/resolved sensitive query names and values are included. The backend runtime's `captureCurrentUrl` (`crates/script-runtime/src/pm.js:111`) also visits the subscription URL during `captureCurrentRequest`; scope set/unset captures both before and after mutation. Thus a transient `opaque → access_token/api_key → opaque` alias retains the credential even if the script throws. Existing regressions passed for direct failure, transient aliases, console feedback, a cross-origin redirect and a target 4401 close echo. Server error feedback, summary/logs and close events in those cases did not contain the known credential.
