# MoleAPI implementation plan
Authority: docs/FEATURE-MATRIX.md, docs/CONFIGURATION-OPTIONS.md, docs/specs/database.md and user's explicit instruction to begin implementation after research.

Preserve the full target matrix, implement vertical modules continuously, and verify before marking any target complete. Prototype-only handlers, empty controls, stub protocol clients and declared-but-untested database support never count as completion.

1. Foundation backend: shared typed HTTP models/executor; SeaORM storage across SQLite/PostgreSQL/MySQL; auth/setup; workspaces/revisions/history; native sync; API routes; embedded binary; core and router integration tests. Root owns formats crate and UI; one implementation subagent owns crates/core and crates/server.
2. Workbench and interchange: mature React/Radix/CodeMirror interface with environment/collections/request edits, response, history, assertions, examples/mock/docs, import/export dialogs, runner and native sync. Rust oas3/openapiv3/jsonschema parse/validate/preserve specifications; support Postman2.1 and3.0 interchange using versioned typed/schema handling.
3. Protocol and script modules: HTTP/SSE/WebSocket/Socket.IO/GraphQL/gRPC/MQTT/SOAP/MCP/A2A/Data clients; separate session/event models, mature libraries; bounded JS runtime and versioned pm compatibility; scoped vars/local overrides/Vault; declarative scenes and datasets.
4. Testing/Mock/publishing: rule/example/schema/script Mock, collection/scenario/suite runner, CSV/JSON datasets, load testing, schedules/self-hosted workers, report persistence/export and document publishing/versioning.
5. Collaboration and extensibility: memberships/roles/invites/comments/team environment, branch/diff/merge, Git source files, CLI/runners/reporters, integrations, AI/MCP workflows and enterprise adapters. Implement each documented target with explicit limits and dependency checks; vendor global marketplace/billing replicas remain product-boundary entries, not fabricated local features.
6. Distribution: Tauri IPC with local SQLite, no local HTTP server; platform icons/packages, server embedding, Docker/compose, real GitHub Actions builds and tests on three database engines. Resolve actual failures; keep tests/network policies meaningful.
7. Independent review of each major backend task and final integrated change; fix material findings, verify UI in agent-browser, then publish tested code and artifacts via configured SOCKS5 git proxy. Main already contains research; implementation in linked worktree feat/application.

Interfaces: docs/API-CONTRACT.md remains transport contract for initial backend/UI; extend backward-compatibly with separate resources, canonical specs and protocol sessions. Core shared schema models are not overwritten by frontier features; JSON defaults keep older data readable. Server constructors local(Path)->Router and hosted(Config)->Router; Config database_url replaces initial SQLite-only database_path. Native token stays in Rust, account/server sync bases durable.
