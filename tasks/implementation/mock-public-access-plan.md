3. [ ] Add bilingual hosted share management to the request editor: one-time copyable URL, expiry, explicit dynamic permission, reload metadata and revoke/rotate. Hide unreachable public sharing for an offline native workspace. Verify actual 390px browser and real public GET/POST calls.
4. [ ] Run full relevant suites, strict Clippy/format/build, independent functional/security review, Application CI, Docker and native package gates. Merge the hosted slice with exact evidence; keep native local listener and broader permission rows open.
5. [ ] Add an explicitly controlled local native public listener with the same share contract, cancellation and installed-platform evidence. Re-audit `mock-011` only after hosted and native behaviors both satisfy its scope.

Storage decision: a digest-derived primary key in the existing `documents` table gives O(1) lookup without a new migration or an owner-wide scan. No raw token is written to the database. Create/rotate/revoke and workspace deletion serialize on the owner/workspace row; public calls re-read the share after response construction so a second process sees revocation before bytes are served. A database outage denies access. Shares are capabilities, not versioned workspace source, and are intentionally absent from MoleAPI backups.

Hosted source checkpoint, 2026-10-17: management and public routes, request-digest rebinding on rotation, generic public errors, admission cap, cross-instance revocation, a bilingual one-time-address dialog and the mobile browser flow are implemented. Seven hosted share, two SQLite database, fourteen existing Mock, five Mock log and 364 frontend cases passed locally, as did focused strict Clippy and embedded builds. Exact-head CI, PostgreSQL/MySQL, native packages and independent review are still required before merging. The explicit native listener remains step 5.
