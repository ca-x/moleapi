A2a-rs 0.10.0 supplies the maintained real server fixture. No gRPC/ConnectRPC UI claim, version translation or models-only client. Each invocation injects a freshly checked, pinned, no-proxy, no-redirect HTTP client with shared auth, headers, TLS, query, timeout and typed JSON variable resolution. The SDK receives only the explicitly selected endpoint; it cannot negotiate to another advertised URL. Files/data remain agent message parts. No local file fetch, OAuth or automatic push registration.

The boxed flattened `A2aConfig` stores dialect, transport, operation, params_source, optional card_source and interface_url. Incomplete bounded drafts save. Canonical `Specification.kind=a2a-agent-card`, dialect `a2a-0.3|a2a-1.0`, preserves exact original source and vendor fields. Selecting specification_id attaches that canonical card at session creation and validates the selected version/transport. Different interface_url requires explicit adoption into request.url.

Card routes: POST `/api/a2a/cards/import` accepts workspace_id, source, dialect, environment_id?, locals?. POST `/api/a2a/cards/discover` accepts workspace_id, request, environment_id?, locals?, discovery_id?. POST `/api/a2a/cards/discover/cancel` accepts workspace_id and discovery_id. Unsaved candidate response contains specification, card, dialect, interfaces[{url,transport,version,supported}] and warnings. Exact `.json` URLs are fetched directly; base URLs use origin `/.well-known/agent-card.json`. Discovery is bounded to four active operations per owner and 32 globally; Stop, logout, workspace/request deletion and final admission fences abort or reject late results. Target 401/307 remain visible upstream failures, never MoleAPI logout. Deletion returns local 404. Source keys, scalar values, raw text and HTTP URL userinfo/query metadata are screened before typed parsing or persistence.

Existing session commands: `a2a_request{request_id,method,params_source}` and `a2a_stop{request_id}`. Operations map directly to actual SDK send, stream, get, cancel, resubscribe, task list (1.0) and explicit push configuration CRUD. UI method aliases are message/send, message/stream, tasks/get, tasks/cancel, tasks/resubscribe, tasks/list and tasks/pushNotificationConfig/set|get|list|delete. Events: a2a_ready, a2a_result, a2a_stream, a2a_error and a2a_finished. Results preserve actual task/context/status/history/artifact semantics; local Stop keeps the session open and remote task cancel is separate. Streams settle on the legacy final flag or actual current settled/interrupted states; transport completion invents no task status. Session readiness opens a local command queue without an invented HTTP 200 handshake. All worker futures abort on cancellation or lease expiry.
