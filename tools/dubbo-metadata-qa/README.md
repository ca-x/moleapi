# Apache Dubbo metadata report fixture

This separate fixture starts an official Apache Dubbo 3.3.6 provider with Curator's embedded ZooKeeper and a ZooKeeper `MetadataReportConfig`. The provider publishes `FullServiceDefinition` for `fixture.RegistryService`: the method, parameter/return types and original JSON are read through Apache `MetadataReport.getServiceDefinition`. The test proves that metadata lookup does not execute the business method. A second digest-protected run proves anonymous and wrong-password reads fail.

Rust checks every resolved metadata-center address, gives the mature ZooKeeper SDK only a pinned literal IP, reads `/dubbo/metadata/<service>/<version>/<group>/provider/<application>` under one deadline, caps the original definition at 1 MiB, and checks its service and method outline. The driver compares the exact original JSON bytes with the Apache API result. Hosted private-IP policy must reject the same endpoint.

The product endpoint is owner-scoped. Preview shows the method outline and original document without changing the workspace. Import requires a saved source request, matching SHA256, expected workspace revision, and an explicit add/skip/replace decision for each method. Existing matching methods default to skip. A linked `dubbo-metadata` specification retains the original definition and metadata endpoint; default backup screens nested secrets, while explicit private export preserves the source. Generated arguments start as `null`, and metadata credentials are not copied to each generated method.

CI builds the official Java fixture and retains JSON evidence plus Java logs. Local JRE/ECJ builds may pass `--classes` and `--dependencies` to `python3 tools/dubbo-metadata-qa/verify.py --java /absolute/java --output /tmp/metadata-evidence.json`.
