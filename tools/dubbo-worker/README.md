# Official classic Dubbo worker candidate

`Worker.java` invokes the official Apache Dubbo3.3.6 `GenericService` once per process. It accepts at most1 MiB of JSON on stdin and emits at most1 MiB of JSON on stdout. The Rust host must supply a checked literal IP endpoint and kill the process on cancellation/deadline; this worker independently refuses hostnames. Its Maven build pins Dubbo, Netty, Fastjson2, Guava and logging dependencies and creates a shaded JAR for the bundled Java21 runtime. No runtime download or user-provided classpath is permitted.

Run38777521075 called the prior worker against an actual Apache Java provider for string, multiple arguments, exact 64-bit integer, typed DTO wrapper, list, null and remote exception, plus hostname refusal. That shaded JAR SHA256 is `fc91d31d99aff504cd33baabb96c454e1562b5bad5a29ed2a14d6b0a293f4709`. Run38781265351 passed the Rust checked host with this JAR; its hosted QA stopped on a fixture output-path assertion before the API call. A later local JRE/ECJ overlay of the corrected Worker class called the same Apache provider over literal IPv6, while the old JAR rejected the bracketed IPv6 host. The corrected source needs its own shaded-JAR hash and CI rerun before replacing the pinned Rust hash. Hosted CI, package resources on every OS and registry/metadata paths remain open; the dedicated editor is now implemented and its actual IPv4 call/history privacy were checked locally.

Build in the manual `Classic Dubbo interoperability QA` workflow. The official generic client is checked before the worker, and `worker-evidence.json` records the shaded JAR hash and actual result cases. The worker's own process-level one-shot design keeps each request's credentials and class metadata from leaking into a reused JVM.
