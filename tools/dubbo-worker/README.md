# Official classic Dubbo worker candidate

`Worker.java` invokes the official Apache Dubbo3.3.6 `GenericService` once per process. It accepts at most1 MiB of JSON on stdin and emits at most1 MiB of JSON on stdout. The Rust host must supply a checked literal IP endpoint and kill the process on cancellation/deadline; this worker independently refuses hostnames. Its Maven build pins Dubbo, Netty, Fastjson2, Guava and logging dependencies and creates a shaded JAR for the bundled Java21 runtime. No runtime download or user-provided classpath is permitted.

Run38777521075 called an earlier worker against an actual Apache Java provider for string, multiple arguments, exact 64-bit integer, typed DTO wrapper, list, null and remote exception, plus hostname refusal. After IPv6 correction and explicit QoS/file-cache disable, run38792444974 produced the current JAR: 19,236,059 bytes, SHA256 `154c9a82bdebc496319880c13731b0444f47a840458328a3810bc1402443dd56`. Eleven worker profiles passed there; its Rust host used the previous pin and correctly rejected the changed bytes. The synchronized Rust/manifest pin now passes local checked-host, exact JAR/JRE staging and real hosted owner/history/group/attachment checks. CI full-chain/package jobs and registry/metadata paths remain open. The dedicated editor has also completed actual IPv4/`localhost` browser calls with private-history redaction using the prior verified worker; the hardened JAR browser rerun remains a separate gate.

Build in the manual `Classic Dubbo interoperability QA` workflow. The official generic client is checked before the worker, and `worker-evidence.json` records the shaded JAR hash and actual result cases. The worker's own process-level one-shot design keeps each request's credentials and class metadata from leaking into a reused JVM.
