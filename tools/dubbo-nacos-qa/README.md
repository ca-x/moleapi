# Nacos provider discovery fixture

This independent QA uses Apache Dubbo 3.3.6 with the matching Nacos client 2.5.1 and the official Nacos server 2.5.1. The server archive is pinned to 153,752,952 bytes and SHA256 `e0877b8e5e8f234694f595a0f25b978c3745325e8b17625b7ab95661e5d3d38e`; `verify.py` checks both before extraction. The fixture registers a grouped/versioned service, checks official `NacosRegistry.lookup`, holds it for Rust's bounded HTTP instance-list lookup and real pinned Dubbo RPC, then checks removal after unexport. The result must match the official provider URL exactly. No lookup path should call the business method.

The Rust source accepts only `nacos://host:port` with explicit Dubbo version and group, in Nacos's public namespace without credentials. It resolves and admits all registry addresses under the hosted network policy, pins one address for a single Nacos instance-list GET, disables proxy/redirect/decompression and caps response bytes. Each healthy, enabled instance is rebuilt from its IP, port and metadata; every resulting provider still passes the shared Rust URL and destination checker before direct invocation. This API route avoids the hidden additional gRPC connection of Nacos's Java naming SDK. Other Nacos versions, authentication, custom namespaces and EDAS need separate fixtures.

An optional bounded `registry_namespace` source field now selects a custom namespace through Nacos' `namespaceId` query, while the saved endpoint remains `nacos://host:port`. The fixture creates `moleapi-qa`, proves public isolation and runs official lookup, exact URL mapping, product RPC and removal in public and custom namespaces. Authentication, other Nacos versions and EDAS still need separate fixtures.

The same driver can run `--auth` against a fresh isolated copy of the pinned server archive. It enables Nacos authentication, initializes a test administrator, and verifies anonymous/wrong-password failure plus authenticated lookup and product RPC in both public and custom namespaces. Rust limits login response bytes and sends the access token in a header to the same pinned private address. Authenticated Nacos over HTTP rejects public destination IPs; TLS and other server versions remain unverified. CI retains separate authentication evidence/logs with fixture-only credentials.

CI builds the fixture with Maven and JDK21, downloads the exact server archive and retains bounded evidence and logs. For local verification, compile the Maven fixture, then run `python3 tools/dubbo-nacos-qa/verify.py --java /absolute/java --jar /absolute/engine.jar --archive /absolute/nacos-server-2.5.1.tar.gz --output /tmp/nacos-evidence.json`. The driver starts and stops its own server and provider; `--classes` and `--dependencies` permit an isolated JRE/ECJ build when a JDK is unavailable locally.
