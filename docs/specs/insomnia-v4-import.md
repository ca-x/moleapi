# Insomnia V4 JSON import

Authority: `interchange-014` in `docs/FEATURE-MATRIX.md`, the official Apifox Insomnia V4 import instructions, Kong's V4 resource format description, and the existing shared formats/owner/CLI contracts. This is one finite import profile, not a claim that all Insomnia exports or `interchange-014` are complete.

## Objective and source contract

- `format=insomnia` accepts one UTF-8 V4 JSON export with `__export_format: 4` and a flat `resources` array. This profile accepts exactly one workspace resource, up to 1,000 HTTP request resources, 1,000 folders and 100 environments. Maximum source size is 5 MiB so the exact original can be retained in a saved `Specification` under the existing per-source limit. Reject duplicate IDs, dangling parents, cycles, more than one workspace and unsupported executable/request-like resources atomically. Preserve resource order within each folder; ID placeholders such as `__WORKSPACE_ID__` are ordinary unique source IDs.
- Map `request_group` or `folder` resources into collections with parent relationships. Requests become normal HTTP requests under their parent collection; a workspace-level request goes into one root collection. Names and descriptions remain editable. Only absolute HTTP(S) URLs or URLs with a finite `{{ _.identifier }}` environment placeholder are accepted; rewrite that exact Insomnia placeholder to MoleAPI's `{{identifier}}` and require the identifier to exist in an imported environment. Other template tags and unresolved variables reject rather than becoming accidental wire text.
- Preserve enabled headers, exact URL query, repeated parameters, and explicit Cookie/Authorization headers. Treat URL query as the wire authority; if the structured parameter list duplicates it exactly, avoid sending it twice. A contradictory list rejects. Omit only transport-owned headers with warnings, using the HAR import header policy. Disable the live Cookie Jar when an explicit Cookie header is imported. No captured credential is treated as renewable authentication.
- Support no body, literal JSON/text and URL-encoded form bodies. For `application/x-www-form-urlencoded` parameter bodies, preserve repeated fields and empty values in order. Missing file bytes, binary and multipart bodies, plugin tags and unsupported MIME types reject. Support explicit Basic and Bearer authentication objects only when their fields are literal and non-conflicting with an Authorization header; reject unsupported auth modes. Request execution still uses the common network/admission limits after import.
- Import the base environment's flat string/number/boolean/null values as editable variables; accept one level of child environments by overlaying base values in separate MoleAPI environments. Nested objects/arrays and deeper environment inheritance reject. Mark sensitive keys as secret according to the existing privacy rules. No environment is silently selected when several child environments exist. Cookie jars, response history, tests/scripts and non-HTTP resources that cannot be mapped without changing semantics reject; harmless workspace metadata may be omitted with a warning.
- Retain the exact V4 source in one `Specification { kind: "insomnia", dialect: "v4" }` for explicit full MoleAPI backup. The default privacy backup clears the opaque source while preserving mapped, screened requests/variables. External Postman/OpenAPI/HAR export rejects until source-preserving mappings are proven. Do not execute or download anything while importing.

## Evidence and boundaries

- A version-pinned V4 fixture covers nested folders, two HTTP requests, repeated query/form fields, Basic/Bearer and literal headers, base/child variables and exact original source. The importer returns one validated workspace or an error. Cases reject duplicate/cyclic/dangling resources, contradictory query metadata, unknown auth/template/body and file/response/script resource loss.
- Hosted owner-scoped import/save/reload and CLI process import use the shared converter. A real browser imports a V4 file in English and Chinese at 390px, reloads, then sends one imported request to a local checked fixture. Default/full backups prove secret screening and exact original retention. Run formats/server/CLI/frontend suites, strict Clippy, formatting, production frontend then embedded server build, independent review and exact-head three-database/Docker/native CI.
- Insomnia V5 YAML, multiple workspaces, response history, tests, plugins, WebSocket/gRPC, file/multipart bodies, full environment inheritance and automatic data-source sync remain open. The original 395-item objective and release/install gates remain unchanged.

Build: `npm run build` in `web`, then `cargo build -p moleapi-server -p moleapi-cli`. Test: `npm test -- --run` in `web`, `cargo test -p moleapi-formats -p moleapi-server -p moleapi-cli`. Preserve source fidelity, owner isolation and default privacy; use existing parser/network engines and do not add runtime downloads.
