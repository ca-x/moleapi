# OAuth1 authorization and private tokens

Complete OAuth1 management beyond request signing: signed request-token exchange, browser/PIN authorization, signed access-token exchange, automatic hosted/native-loopback callbacks and manual completion, owner/workspace-bound private access-token storage, list/import/select/rename/reveal/copy/delete. Use the existing oauth1-request signing adapter, checked reqwest transport, URL/serde_urlencoded parsers and SeaORM document transactions. OAuth1 has no standard refresh/introspection/revocation API; local deletion must not claim provider revocation.

Optional grant settings and a token_id extend OAuth1Auth backward-compatibly. Grant settings contain request-token, authorization and access-token endpoints, callback URI, and enabled custom request/access form parameters. Request execution ignores unused grant settings; selected vault credentials override inactive saved token drafts without changing source. Source interpolation resolves only operation-relevant fields. A selected token needs the private owner broker; direct core execution rejects unresolved token IDs.

The vault profile binds version1, resolved consumer key and canonical provider endpoints and a grant-purpose fingerprint, excluding credential secrets, callback URI and request signature placement. Private token/secret/verifier never enter workspaces, histories, sync or default source exports. Native explicit source backup preserves source settings but cannot export private vault records. Access tokens persist as private documents with owner+workspace+kind+ID filters; max128 per workspace. Creation locks the parent workspace and checks capacity in one transaction across SQLite/PostgreSQL/MySQL; rename uses revision CAS and deletion checks exact identity. Workspace deletion cascades records. Metadata omits credentials; explicit reveal uses no-store.

Flow state is unpredictable, expiring and owner-authenticated. Max64 flows,8 per owner,8 concurrent exchanges,600s expiry. Request-token secrets stay ephemeral. Request-token replies must confirm the callback. Automatic callback URIs add a random state parameter in addition to checking oauth_token; verifier is required and single-use. Callback endpoints return generic bilingual pages, never token IDs, secrets or provider errors. Native listeners bind only explicit127.0.0.1 HTTP ports; occupied ports fail. Pending network requests/listeners cancel on explicit cancel, logout, expiry and workspace deletion. Owner admission generations and session rechecks prevent late persistence after logout; completion/cancel serialize around the final database write, with workspace deletion sharing its existing gate.

Provider operations use bounded UTF8 URL-encoded responses, reject duplicate mandatory fields, timeout and never follow redirects carrying signed consumer credentials. Provider error bodies are not echoed. Custom parameters reject OAuth-owned names. Request/access exchange nonce and timestamp are fresh per operation, not saved request debugging overrides. Access-token exchange uses only its temporary token/secret/verifier, not a stale selected token.

Bilingual Radix management dialog retains owner/workspace/environment/collection context. Generation guards cover close/reopen, configuration changes and late begin/poll/reveal responses; inactive flow cancellation must still happen when a begin response arrives after close. Automatic completion selects the issued token only in the unchanged editor context. Persist unsaved workspace scope before network exchange. Tests target real signed exchanges, response parsing, PIN and hosted/loopback callbacks, single-use/wrong-state/wrong-token behavior, cancellation/logout/deletion races, vault privacy/owner/profile/source preservation and relevant UI stale-context behavior. Use necessary targeted checks and actual embedded browser; final release remains contingent on the full remaining feature scope.

## Implementation evidence and boundaries

The implemented core uses serde_urlencoded for mandatory-field duplicate detection and URL-encoded token replies, rejects invalid decoded UTF8, requires oauth_callback_confirmed=true, caps replies64KiB and does not follow endpoint redirects. Request/access exchanges override saved token/debug/callback fields per operation. Request signing ignores dormant grant fields; selected credential drafts are replaced only by the owner broker.

Vault profile version1 also hashes ordered, enabled noncredential request/access parameters. Scope/audience/resource/tenant/username identity fields remain bound even when marked private; password/client-secret/other marked credential extras do not become dependencies of API request execution. Changes to issuer/client/purpose require a compatible token or reauthorization. Custom parameter local_value metadata is not an execution override: use scoped local environment variables instead. Hosted/sync source scrubbing removes those local values; default source exports screen them. Postman export rejects selected vault references. Native explicit source backup retains source and references but excludes the independent private vault.

Five real server cases cover PIN, hosted wrong-token/single-use/denial callbacks, owner-bound import/reveal, persisted records reopened through independent storage connections, environment/client/purpose profile checks, real loopback ports/occupied-port errors, deletion/cancellation/logout races and redacted history. Core tests cover real signed exchanges and invalid/oversized/duplicate/redirect responses; prior RFC/Postman signing vectors stay green. Interchange checks cover safe/default versus explicit source backups, templated endpoint queries and private extras. Four React cases cover late begin, close/reopen reveal, in-flight cancellation and changed same-environment variables. Relevant catalog/editor checks, production TypeScript build and strict Clippy/fmt passed.

The common configured-database suite exercises OAuth1 private import, reopening, rename, ownership and cascade on SQLite/PostgreSQL/MySQL. Local evidence currently covers SQLite; actual PostgreSQL/MySQL evidence must come from GitHub Actions. Agent-browser exercised embedded request-token → provider authorization → automatic callback → access-token selection → independently signature-verified resource request, plus English/Chinese and390px layout. Native loopback HTTP is tested; native graphical installers remain a separate release gate.

OAuth1.0a exchanges use POST and URL-encoded responses; legacy providers lacking callback confirmation must use manually supplied credentials. Automatic callbacks require a provider that preserves the appended state query. Flow state/listeners are process-local and expire in600s, requiring affinity on multi-process hosting and reauthorization after restart; access-token records persist. Delete is local deletion, not remote revocation. These are explicit protocol/operation boundaries, not claims of unimplemented proprietary provider extensions or full product parity.
