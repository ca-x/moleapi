# Akamai EdgeGrid authentication

Complete auth-013 using the existing tropel-auth0.6 pure EdgeGrid builder with documented, Apache-2.0-preserved interoperability corrections. The SDK and RustCrypto own hashing/MAC/header construction. Finite HTTP/SOAP/GraphQL calls sign actual prepared URL/query/headers/body. Add access/client tokens, client secret, optional signing base URL, ordered selected headers, nonce/timestamp overrides and max hashed body bytes. Default max is131072; POST hashes only the prefix, while the full body is sent. Other methods have an empty content hash. No default-file credentials or ambient network.

EdgeGrid timestamp is yyyyMMddTHH:mm:ss+0000, not RFC3339. Fresh nonce/time are generated per execution/hop. Tokens/nonce cannot inject semicolon/tab/control fields. Signing owns Authorization, validates selected header names/values and preserves their order without duplicate ambiguity. Signing base URL affects authority only; actual checked transport destination/scheme/path/query remain authoritative.

Auth source stays modular/backward compatible, preserves inactive drafts, uses environment/global/folder/workspace inheritance, and privacy captures credentials plus generated headers/signatures across history/default exports. Same-origin redirects re-sign actual method/body; cross-origin redirects disable signing and strip credentials. Unsupported live/generation/source mappings reject explicitly. Bilingual Radix fields use existing interaction/motion tokens.

Verify independent Postman computeHeader vectors for nondefault ports, Unicode/duplicate queries, selected-header whitespace/order, empty/binary/oversized POST prefixes and non-POST bodies. Exercise actual HTTP payload preservation, redirects, inheritance/vars/history/privacy/native/Postman roundtrip and necessary UI/locale/build gates. Features first; final desktop/server/Docker builds and publication occur on main via GitHub Actions after full functional completion.

## Evidence and operation boundaries

Eight independent fixtures use Postman Runtime's computeHeader, including exact byte-prefix hashing at a multibyte UTF8 boundary. All match the Rust SDK output. Three core cases cover vectors/input rejection and actual untruncated POST/303/cross-origin behavior; one server case covers inherited unmarked credential variables and generated-history privacy. One native/Postman interchange case preserves header order/base URL/hash limit/time/nonce and screens copied secrets. The editor/catalog checks, strict core/server/formats Clippy and production TypeScript/embedded builds pass. The patched EdgeGrid SDK module independently passes22 preserved/corrected unit cases; unused providers from that crate are not part of this integration.

Agent-browser exercised the actual embedded bilingual editor and sent four binary bytes with a three-byte hashing limit to an independent Postman signing verifier, which authenticated the header and reported the complete body.390px viewport has no horizontal overflow. Runtime time/nonce are generated locally and do not rely on optional SDK transport features. TLS/private-network/timeout checks remain in the shared transport.

Signing base URL is parsed/canonicalized with the same mature URL rules used for transport, including default-port normalization; it changes signing authority only. Selected header names are ordered and trimmed, missing/empty values are omitted, and duplicate selected names or duplicate wire values reject as ambiguous. Postman concrete numeric hash limits and string/array header lists map; a templated numeric maxBodySize is retained in the original source with execution disabled and a reconfiguration warning. Native limits are1..5MiB, consistent with the body cap. Raw credential/nonce delimiters and non-UTC/wrong-format timestamps reject. Multipart signing covers actual encoded bytes, while Postman Runtime itself does not compute multipart body hashes; original/native source remains available. Request snippets/OpenAPI/live signing adapters are separate required mappings, not claimed complete by this provider.
