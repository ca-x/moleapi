# Declarative response extraction

Required response-to-variable functionality, distinct from existing handwritten post scripts. Add ordered enabled/required extraction rules to RequestSpec: id/name/kind/target/scope/key. Keep old requests compatible via empty defaults. Support body, case-insensitive header, JSON Pointer, JSONPath, XPath1.0 and regex first-capture/full-match through existing mature Rust libraries. Reuse the bounded assertion worker, not another parser/engine.

Successful values become ordinary string/JSON-encoded variable updates. Extraction runs after network/assertions and before post scripts, so post scripts and subsequent collection requests can read the updates. Scopes are temporary/environment/collection/project; environment requires the selected environment. No canonical workspace write happens on the server. Browser/native local update mechanisms handle returned values exactly as script setters do. All extracted values are privacy-tainted before history persistence, even on application/quota failure. Missing/invalid required extraction fails a check; optional extraction only records a fixed warning. Do not echo response/private values into errors or truncate a value into a different stored secret.

At most100 rules,4 KiB selectors,64 KiB individual values and1 MiB total updates. Disabled rules do not execute. Binary/truncated bodies fail structured/body extraction; headers remain available. Root XML namespace prefixes are supported; external resources/DTD remain disabled. Query evaluation occurs under existing512 MiB/2s/input/output worker limits, owner/cancel gates and network policy. Actual values are live-only in returned variable_updates; histories clear those updates and redact copied values.

UI uses existing Radix selectors/inputs to define rules with names/source/path/destination/key/enabled/required. Provide clear scope/ordering explanation and preserve owner/source fences. Tests: typed/multiple JSON matches, XML/regex/header/body; required vs optional/missing, per-environment scoping, variables available in post/next request, history privacy and unchanged canonical values; worker failure and editor/catalog/type/build. No intermediate formal review is requested; full release objective remains unchanged.
