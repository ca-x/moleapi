# Native hosted shared workspaces

## Objective

Complete the native-client part of `member-workbench`: after connecting the existing native hosted session, users can accept invitations, list/select role-labelled remote shared workspaces, edit/save/run and use every currently supported shared protocol/Mock/data/report/source control. Remote members act against canonical owner revisions; no remote shared workspace becomes a local owned workspace or enters the owned push/pull sync bases.

## Data flow and boundaries

The existing local Axum API is the only native frontend bridge. New local-only `POST /api/sync/collaboration` accepts a deny-unknown-fields JSON request `{session_id, method, path, body?, mode?}`. `session_id` is the public opaque connection generation, never the stored bearer token. `path` is a relative application API path. An explicit method/path allowlist permits shared-workspace listing, invitation acceptance, registered owner/workspace member operations and the shared Dubbo capability check. It excludes auth, vault, runner/agent, owned workspace, public-share management, raw wildcard routing and arbitrary hosts. A `mock_preview` mode is restricted to the existing direct member saved-example GET; all other calls use JSON mode. The new JSON route debugger is an ordinary JSON operation.

Parse URI/path/query with existing http/url/percent-encoding utilities. Decode path segments once, reject empty/dot/slash/backslash/control segments and reconstruct fixed-origin paths with URL path_segments_mut. Query is bounded to8192 bytes and only existing route-specific cursor/after/format keys; never a bearer token. Retain repeated query values if supported by the upstream route. Request JSON maximum25MiB, response JSON maximum25MiB, raw Mock preview maximum5MiB; native IPC reply maximum32MiB accommodates worst-case JSON escaping of that bounded raw body; bound streams even without Content-Length. The new bridge does not carry caller Authorization/Cookie/Host or upstream Set-Cookie/Location headers. Withhold responses that copy the current stored login bearer in raw text or JSON-normalized strings/keys, including JSON-formatted raw previews, rather than returning that credential to JavaScript. Use only the configured connection token, existing HTTPS/loopback policy, DNS pinning, no proxy and no redirect. Existing native owned sync/runner gateway contracts remain compatible.

Capture connection under sync_lock, check exact nonempty session_id before forwarding, then release the lock before network I/O. A100ms connection-generation watcher and final locked check withhold output after disconnect/reconnect/account/server changes. They cancel the actual HTTP future and bounded body read; no mutating operation is retried automatically. A lost response after a remote Save has an unknown outcome and must refetch current canonical revision before another explicit Save. No lock is held throughout long calls: Stop/disconnect/reconnect can proceed. After local disconnect or successful replacement commits, attempt to revoke the previous stored hosted login outside the lock, bounded to750ms. Skip revoking an identical origin/token reused by an older server. Reachable hosted logout lets existing creator-bound remote sessions observe credential revocation and close; offline revocation is best effort and cannot promise immediate remote cancellation. The upstream server remains authoritative for role, actor credential, membership epoch and workspace/request revision; preserve its HTTP status and JSON error inside the local envelope. No raw HTML/header reaches WebView navigation/cookies.

## Client behavior

Keep native local account/authentication separate from remote member identity. A dedicated public connection-generation marker supplies shared control guards; no hosted bearer token is returned to JavaScript. Route only member API paths through the bridge and scope every request to the generation captured before dispatch, including capability checks and direct Mock previews. On a changed connection or remote401, clear shared drafts/query caches/results/selection and discard all retained callbacks. A late error from an old connection must not disconnect a new one. Preserve local owned workspace, native file dialogs and native save behavior. Invitations and role-labelled picker use the connected hosted account; local offline workspaces retain their independent ownership and explicit existing migration flow.

Remote shared data may live only in account/generation-scoped memory query caches; remove caches on disconnect/reconnect. The feature queues no offline writes and shows disconnected/unavailable state. Current saved data is re-read from hosted service after reconnect, with explicit revision conflicts; no stale replay or overwrite. Temporary protocol data/Mock inputs stay scoped to the current member view. Remote execution and remote capability discovery must use the hosted service, including Dubbo worker availability. Existing file-pick/save controls stay local, with current-context checks around dialogs/downloads.

## Structure and style

Backend: `crates/server/src/sync/collaboration.rs`, existing sync connection/client helpers, local router and explicit route policy inventory. Tests in `crates/server/tests/sync_collaboration.rs` use actual hosted+local routers and wire HTTP with canonical same-ID collision fixtures.
Frontend: dedicated native member session state/transport helpers, shared API adapter, useSync/controller connection boundary and settings/picker integration. Shared components consume a member credential accessor, preserving normal web token behavior. Reuse existing React Query, Radix controls, file APIs and mature response inspectors; no dependency, custom HTTP parser or copied protocol implementation.

Example: `let result = forward(&snapshot, request).await; ensure_session(&state, &snapshot.session_id).await?; result` with the watcher covering both forwarding and bounded reads.

## Boundaries

Always: actor/session/revision fencing, privacy and bounded I/O, RED→GREEN regressions, one independent final review, actual wire and UI evidence before delivery. No automatic retries or owner identity overrides. No stored hosted credentials in frontend/query cache/artifacts.
Standing user authorization covers completing remaining planned features and routine commit/push/PR delivery. No new dependencies/schema/publishing/credential request is required. Real EDAS remains unavailable and is not requested again. Keep the full28-module395-capability goal active after this capability.
