## Filesystem inputs for regeneration

Regeneration accepts a previous untouched generated ZIP alongside the existing snapshot JSON, and current edited directory/ZIP inputs. Rust `rawzip`0.5.2 checks every central-directory entry with its zero-copy iterator, including duplicates and entry counts; `zip`4 owns decompression/CRC validation in the existing capped/cancellable project worker; no archive extraction or imported-path filesystem access occurs on the server. ZIP filenames must be UTF8. Previous ZIPs require a valid `moleapi-generation-v1` manifest and exactly matching regular-file names, hashes, sizes and executable flags. Edited input hashes are computed from current bytes, without validating against stale generator metadata. Regeneration metadata is removed from current input to allow importing the last merged ZIP again.

ZIP imports reject traversal/absolute/backslash paths, duplicate names, file/directory collisions, symlinks/special nodes, encryption/unsupported compression and oversized expanded content. A single enclosing directory is stripped only when it contains the recognized generation/regeneration manifest. Apply 10 MiB compressed, 4 MiB per file, 8 MiB content plus 512 KiB metadata and 2048-file/4096-node limits before and during reading. Preserve safe executable flags. Empty edited inputs can represent deletions. Reuse owner/workspace admission, quota, cancellation and post-job identity checks for imports.

Browser directory selection uses file-picker relative paths and omits the selected root directory. Native directory selection grants access only through the user's dialog, rejects links/special files, bounds traversal/read sizes and preserves Unix executable flags when available. Browser and native Windows directory files inherit known baseline executable flags when the picker cannot expose Unix permission bits. Native scoped filesystem patterns include dotfiles inside the dialog-selected directory, while VCS/dependency directories remain excluded. Directory selection excludes `.git`, `.svn`, `.hg`, `node_modules`, `target`, `.venv`, `__pycache__` directories with explicit UI help; ZIP imports keep authored content. Missing edited files remain deletions and added regular files remain authored content. UI shows previous/current file counts, distinct import/merge states and cancellation; close/reopen, account/workspace/content changes and new selections discard late results. Export is a new archive; imported files are never overwritten.
