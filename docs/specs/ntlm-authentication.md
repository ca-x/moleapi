# NTLM authentication

Implement auth-012 as a finite HTTP/SOAP/GraphQL request provider using Devolutions sspi0.23 for NTLMv2 tokens/challenge processing/MIC and RustCrypto through the SDK. Explicit username/password, optional domain and workstation, and optional TLS channel binding have a bilingual mature-component editor with environment variables and inherited authentication. No implicit OS credential lookup and no homemade NTLM crypto/wire-message parser.

Connection affinity is mandatory: use Hyper's HTTP1 connection sender on one checked/pinned TCP/TLS socket for anonymous→Type1→Type3 requests. Drain bounded401 bodies before continuing. Never reconnect/retry a Type3 on a replacement connection. Abort and drop the owned connection driver on cancellation/timeout. Do not share authenticated sockets across requests/accounts; a same-origin redirect starts a new handshake/socket for its new hop, and cross-origin redirects disable NTLM. Exact materialized method/query/binary/multipart body is replayed; headers/cookies use the existing shared pipeline. Connections declining keep-alive during a challenge reject explicitly. At most two auth retries; final401 remains an actual response rather than an infinite loop.

Existing DNS/private-network, downgrade, TLS verification, timeouts/body caps and transport-owned header policies remain authoritative. NTLM is only offered for finite HTTP transports; unsupported live/protocol/generation mappings reject rather than claim compatibility. Default source exports clear all credentials and screen inherited/env/copied identities. Generated Type1/Type3 values are ephemeral and private history values. Native explicit backup and verified Postman domain/workstation source mappings remain available.

TLS binding hashes the peer certificate using a mature X509 parser and RustCrypto hash algorithms according to RFC5929, with weak certificate-signature hashes upgraded to SHA256. The SDK constructs NTLM channel-binding AV pairs. Unsupported certificate hash forms reject explicitly when binding is requested. NTLMv1, LM-only, Kerberos/Negotiate fallback and OS integrated login are not silently substituted.

Necessary evidence: mature SDK accept-side verifies an actual HTTP handshake on the same socket; wrong password/status/close/malformed challenge/timeout/cancellation/redirect/body replay; independent Postman NTLMv2 response validation; source/environment/inheritance/history/privacy/interchange; TLS binding and relevant editor/locale checks. No local Docker; actual platform/release gates stay on GitHub Actions.

## Implementation evidence and boundaries

The HTTP adapter owns a Hyper HTTP1 sender on one pinned Tokio TCP/rustls stream; its driver is aborted on Drop. Every redirect discards the NTLM connection/context, same-origin hops negotiate anew, and cross-origin hops switch to the ordinary unauthenticated transport. The original materialized bytes remain replayable for binary/multipart bodies. Bare and combined/token68 challenges use the existing http-auth/www-authenticate parsers. The hyperx compatibility copy changes only three dependency ranges within their existing majors; source and MIT license are unchanged.

Five core integration cases cover SSPI acceptor verification/socket count/exact bytes, password401/connection-close, real TLS binding/certificate trust, redirects, timeout/drop cancellation and malformed Type2. Correct binding is accepted and a deliberately mismatched binding is rejected by the SDK acceptor; its optional binding policy allows an absent binding, so this fixture does not claim Windows Strict EPA validation. Published synthetic Type2/Type3 fixtures are independently verified by Postman Runtime's NTOWFv2/HMAC implementation via `scripts/verify_ntlm_exchange.cjs`; that test-only script reads fixed security-buffer descriptors, while all production NTLM messages are parsed by SSPI.

The relevant shared transport gate passed36 core cases (NTLM, Basic/API/JWT/Digest, OAuth1, cookies, request bodies and network policy), plus the server inheritance/history case, source/privacy/Postman interchange case and four UI/editor/catalog checks. Strict core/server/formats Clippy, package fmt and TypeScript production build passed. Agent-browser sent an actual embedded-page POST through NTLMv2 to independent pyspnego0.12.4 and received authenticated DOMAIN\\User with exact JSON bytes;390px viewport has no horizontal overflow.

TLS binding supports RSA PKCS1 SHA256/384/512, RSA PSS and ECDSA SHA224/256/384/512, upgrading recognized legacy RSA/DSA/EC MD5/SHA1 forms to SHA256; unknown certificate signature hash forms reject when binding is enabled. It does not substitute NTLMv1/LM/Kerberos/OS credentials. Postman NTLM source maps username/password/domain/workstation with binding disabled because its provider has no binding option; native enabled-binding exports reject unsupported external conversion. Root optional settings/identity sources retain inactive drafts, while default exports screen copied credential/identity values. Desktop GUI/installers and complete platform builds remain part of the final release gate.
