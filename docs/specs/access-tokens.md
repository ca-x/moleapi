# Personal API access tokens

CLI/CI automation needs separately managed credentials rather than a browser30-day login session. Add hosted account-owned named personal access tokens with mandatory1–365day expiry (default90), list metadata, one-time plaintext creation response and owned revocation. They inherit the account's existing owned-resource permissions, cannot list/create/revoke other access tokens, and remain distinct from workspace request API keys. The native offline database has no hosted account and must not mint tokens; native clients can continue using explicitly connected server credentials.

Use existing mature rand/SHA256/SeaORM crates. A separate indexed relational table stores UUID ID, owner, bounded label, unique SHA256 digest and creation/expiry timestamps. Never persist token plaintext or include digests in JSON/workspace exports/synchronization. Use an explicit token prefix and32 cryptographic random bytes. Bound each account to100 stored tokens; serialize concurrent creation by locking/updating its existing account row in the same transaction as counting/insertion. Add an additive migration for SQLite/PostgreSQL/MySQL, without modifying previously applied migrations.

Reuse the hosted Bearer guard and admission rechecks with one shared session/PAT lookup. A session-only authentication extension restricts management, so API tokens cannot issue new credentials or enumerate them. Logout with a PAT revokes that PAT. Explicit revocation persists before response and invalidates this instance's existing owner admissions/jobs/protocol sessions using the established logout lifecycle. Future requests on every instance query persisted expiry/revocation; cross-instance in-flight interruption remains broader distributed admission work, not claimed here.

UI: existing hosted settings, separate modular Radix section, named/expiry inputs, metadata list and explicit revoke confirmation; raw token visible only in current creation view, copy once, cleared on dismissal/unmount/account or credential change. Use account/credential-bound queries and late-response fences. English/Chinese copy; existing components/styles and no new decorative motion. CLI: session-authenticated token list/create/revoke subcommands, token input from environment/private file; created tokens go only to atomic0600/no-overwrite output files, stdout contains metadata. Newly created PATs must work with existing remote commands. Necessary API/UI/CLI fixtures cover ownership, one-time/privacy/storage, expiry/revocation and command integration; full matrix/release work remains active.
