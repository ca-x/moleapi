# Data request client

Authority: protocols-017, the active full-capability objective, and Postman data-overview/create-data-request documentation read with agent-browser on2026-10-05. Application storage engines are separate from this client. Deliver independent hosted/native clients for PostgreSQL, MySQL, selected local files and checked remote files, schema exploration, real SQL execution with an explicit read-only option, selected-statement execution, typed results, sort/search/pagination, save/import/export, scoped variables and bounded cancellation. Do not label menu entries or application storage as Data support.

Assumptions grounded in the published UI: local files are selected explicitly, not arbitrary server paths; hosted browsers can upload chosen file bytes. CSV is explicitly documented; provide mature CSV/JSON/Parquet readers. Default database read-only is on; users can turn it off to execute writes/DDL. A single query is executed at a time, chosen from the editor cursor/selection using mature SQL syntax trees. Returned values retain exact text/precision/null/binary identity rather than silently converting large integers to JavaScript doubles. This is a dedicated Data client; reusable datasets/test data integration remain separate required shared capabilities.

## Wire/model contract

Protocol Data flattens DataConfig: source(postgresql/mysql/local_file/remote_file), sql(original editor document), file_name, file_format(csv/json/parquet), file_base64(optional selected local bytes), table_name(default data), csv_header(default true), read_only(default true), tls(default true), ca_pem(optional explicit PEM). Existing request.url carries one DB connection URL or remote HTTP(S) URL; explicit Basic auth fields can replace URL username/password. request.timeout_ms governs operation, request.verify_tls governs actual certificate verification. URL query connection options must be allowlisted; no hidden socket/file/multiple-host option may bypass checked/pinned transport or read user-controlled local paths. Default local-file export withholds opaque file bytes; explicit private export preserves originals. Private URLs/auth/scoped values and copied known private values are screened through existing helpers; original saved/editor values remain exact.

Existing protocol start returns the session; Data ready/schema and query result/error/cancelled events carry real state, stable cursors, query IDs and timings. Commands data_query(query_id, selected_sql) and data_cancel(query_id); Stop closes the session. Query results have ordered columns(name,type,nullable), rows of typed cells(null,text,bool,integer/decimal text,binary Base64/byte length), rows affected, row count, elapsed, truncation/limit reasons. Schema contains bounded schemas/tables/columns and SDK-rendered quoted references. Never execute multiple editor statements through a single query command or infer a target from query text.

## Correctness and resource boundaries

Every DNS address is checked once before connection; original host retained for TLS, checked IPs used for DB and cancellation sockets. Explicit TLS/no-TLS/verification controls; default roots and explicit PEM buffers never load URL-specified filesystem paths. Hosted private-network policy remains enforced. No alternate unchecked DNS/redirect/proxy routes. Owner/session/request fences apply to late results and cancellation. Database/read-only transactions and mature SQL AST validation prevent statement/transaction-control escape; read-only cannot be implemented by a SELECT prefix. Write/schema mode must work when explicitly selected. Database cancellation must report actual errors/ambiguous completion; never claim a write was rolled back merely because the UI stopped. No automatic background queries beyond explicit schema loading/refresh.

Bound files5MiB, query source64KiB/one active statement, AST/work complexity, imported table rows/columns, schema metadata and returned rows/cells/bytes. Set DataFusion memory budgets and disable spill/external stores; only explicitly registered in-memory file tables are accessible. SQL options deny DDL/DML/session statements for files; no arbitrary local/remote filesystem/network functions. Driver packet/frame budgets must be verified before claiming hostile-source bounds. Four execution slots; per-session command/result/input limits follow common sessions. Timeouts/cancel/drop close/reap connection/worker resources. If a query is capped, the UI says so and does not fabricate a complete row count.

## Implementation notes

Exact JSON numbers use serde_json RawValue inside file import; arbitrary_precision is not enabled globally because mature A2A SDK serialization is incompatible with that representation. Homogeneous top-level signed i64 fields remain numeric; decimal/mixed/overflow columns and nested numeric lexemes become exact text for deliberate DECIMAL casts. Query functions retain database privileges; known session settings/locks are rejected with AST identifiers, not a general function sandbox.

Schema reads use independent, promptly disposable SDK transports to the same checked endpoint. Capped database queries keep captured rows and terminate the query connection without draining pending results or claiming write rollback. MySQL enables a documented opt-in SDK transport Drop patch; pooled behavior and wire/auth parsers remain upstream. PostgreSQL aborts its SDK connection task. Clients must reconnect after cancellation, timeout or a capped database query.


CA field validation accepts only complete certificate PEM blocks separated by whitespace, or one whole `{{variable}}` at save time. Mature pem parsing exposes all section labels; DER is checked with rustls. Literal/mixed/encrypted/OpenSSH private keys and unparsed trailing material must fail before persistence. Resolved variable values are checked before TLS construction. Original valid certificate source remains exact; private keys belong to a future explicit client-certificate capability, never the CA field.
