# Durable owned run reports and exports

Implement testing-020/021 on the existing workspace runner. Completed and stopped runs automatically persist an immutable, privacy-projected report in owner/workspace-scoped document storage. Include source workspace revision, collection/scenario/environment/dataset references and names, start/finish UTC timestamps, run/iteration summaries, ordered step/repeat/group/parallel identity, outcomes/status/timing/size, capped assertion diagnostics and omission counts. Keep live network bodies, headers, request mutations, logs, source datasets and variable values out of the artifact; full live results and separate request history remain available. Do not fabricate a passed outcome when a live response was omitted.

Add explicit per-item outcomes/assertion counts before report size trimming. Redact stored display/reference strings and diagnostics with known canonical/runtime privacy sources; omit uncertain script/error diagnostic text. Preserve report UUID/workspace ownership for lookup. Cap1000 steps,4MiB reports,1MiB total diagnostic text and report text-field sizes; record omitted diagnostic counts. Persist the report without changing canonical workspace data. Use a transaction with a no-op workspace-row write lock before existence checking, insertion and retention so deletion cannot leave orphan reports across SQLite/PostgreSQL/MySQL. Keep newest100 reports per owned workspace. Owner epoch changes suppress late persistence; an ordinary user cancellation retains its stopped report. Persistence failure must not erase live results and must be explicitly reported.

Authenticated API: paginated newest-first summaries using an opaque bounded timestamp/ID seek cursor, full lookup, one/all deletion and export. Every route verifies owner and workspace, including report lookup in the requested workspace. Workspace deletion cascades through the existing document mechanism; report deletion leaves interface/request history unchanged. Reports survive service restart and source request deletion.

Exports: JSON through serde_json, CSV through mature csv with formula-leading text protected, JUnit through quick-junit0.8.0, and self-contained bilingual HTML through Maud0.27.0. HTML/XML use upstream escaping, no custom serializer. JUnit distinguishes passed/failed/skipped occurrences and adds an error case for an incomplete/stopped run so CI cannot misread empty/canceled reports as success. Exports never include live variables/body/headers. Bound output bytes. CSV columns remain stable identifiers; fixed HTML labels follow selected English/Chinese locale.

React/Radix report history exposes refresh, details, pagination, scoped deletion and file downloads through the existing browser/native saver. Show persisted report ID/save failures in live results; owner/workspace/result fences discard late responses and picker writes. Link a failed step back to its current canonical request only if the reference still exists. Necessary API fixtures cover persistence/restart, ownership/workspace boundaries, canceled/failed/asserted/multi-iteration/parallel/privacy outcomes, delete/cascade, seek pagination/retention and actual export parse/escaping. Scoped UI/catalog/type/build checks only. Durable job recovery/scheduling/distributed runners, broader orchestration, remaining matrix features and unified review/main release remain required.
