# Data-driven Mock bindings

Status: implementation specification for the declarative part of `mock-012`. This builds on saved datasets, saved read-only views, selected-example dispatch, Mock scripts and public Mock grants. Script-driven dataset access already exists; this adds a visible mapping for owners who do not want to write JavaScript.

## Objective

An owner can bind one saved Mock example to a saved dataset view. When that example is selected, MoleAPI reads a bounded result and returns JSON. Optional parameters come from explicit safe fields of the incoming Mock request. A saved literal dataset and a query-backed Data dataset use the same selected-example path. Static examples remain byte-compatible after upgrade.

## Contract

1. An example may contain optional `mock_data` with `dataset_id`, `view_id`, ordered `parameters` and `shape` (`rows` or `first`). A parameter names one source: `path`, `query` or `header`. At most 16 parameters are allowed. The referenced dataset and SQL-backed read-only view must exist in the same workspace. A data binding and either inline or linked Mock schema are mutually exclusive. An authored Mock script may run after the data binding and modify the response draft. The binding requires script compatibility v2 because it uses the same bounded dataset worker.
2. A selected example alone may access its binding. A nonselected route, simulated fault, rate-limited call, revoked share or failed owner admission never opens a dataset or runs its Data request. Literal datasets use the saved immutable workspace source; query-backed datasets refresh their referenced read-only Data request once for this selected call using the current owner/workspace revision and deadline. Any read, refresh, view, timeout, cancellation or privacy failure withholds the saved example body; it does not fall back to static/schema content.
3. Parameter resolution uses the selected request's matched named path segments, exact one-occurrence query key or exact one-occurrence safe header. Missing or duplicate values reject with a generic client error before the dataset query. Authorization, cookies, credential-like query/header names, hop-by-hop headers and raw request body cannot be bound. Decoded values and the generated query result remain within the existing request, dataset and response budgets. SQL comes only from the saved view; incoming values are bound parameters, never SQL text.
4. `rows` returns the JSON array returned by the existing read-only view engine; `first` returns its first object and yields a generic 404 when no row exists. The example's status and safe headers apply for a result. The server supplies `application/json` when no enabled Content-Type exists, and workspace validation rejects a conflicting authored media type. Existing Mock scripts then receive this JSON draft and can override status, headers or body under their current limits. Final revision and public grant checks still apply before responding or recording a call.
5. Public Mock grants treat a data binding as dynamic content. A public share must explicitly allow dynamic responses, and still observes the same owner/revision/revocation fences. Owner list and call logs disclose only metadata, never query rows, bound parameters or private Data credentials. Default backup withholds private source material under the existing dataset privacy policy; external exports that cannot retain a binding reject it visibly.
6. The bilingual example editor offers a dataset selector, a view selector, ordered parameter source/name rows and response shape. It shows unavailable references and explains that only saved views are selectable. Selection and error states survive save/reload and account/workspace changes cannot apply an old asynchronous response to a new draft. At 390px, controls stay keyboard accessible and do not cause viewport overflow.

## Evidence and limits

Test old-example serialization and saved-workspace validation; literal JSON and CSV views; live Data refresh; path/query/header binding and ambiguous or private values; owner/public permission, revocation, cancellation, source changes, output limits and no fallback; default/full backup and external format behavior; bilingual 390px owner and public Mock flows. Run focused Rust/frontend suites, strict Clippy, production frontend and embedded server builds, then fixed-head three-database CI, Docker and current native packaging. Other Mock rows and the full 395-item matrix remain open.
