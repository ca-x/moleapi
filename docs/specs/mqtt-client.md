## Libraries and modules

Use rumqttc0.25.1 (or verified newer compatible mature Rust SDK) for MQTT3.1.1 and MQTT5 parsing/encoding, connections, heartbeat, QoS0/1/2 handshakes and packet identifiers. Do not implement MQTT framing, subscriptions/ACK state machine or a fake broker. Real broker fixture must use a mature implementation with MQTT5 support, such as rumqttd or an isolated Mosquitto binary; no local Docker or system-service changes. Node Aedes3.1.1 alone does not prove MQTT5 support.

Core owns canonical typed config/message/topic/property/will models, interpolation and validation; protocols owns checked transport+SDK event loop/session adaptation; server owns auth/workspace admission/API; root owns dedicated React/Radix/CodeMirror/chart interface and export. Exact saved DTO/commands/events must be reported to root early before substantial UI work. Keep older workspaces readable; saved incomplete drafts remain editable and execution rejects invalid configuration before networking.

## Saved config and actual capabilities

Broker URL is canonical mqtt:// for TCP, mqtts:// for TLS; support ws/wss MQTT transport if the mature SDK implements it, validating/pinning every actual destination and original TLS hostname. Explicit MQTT3.1.1/5 version selection. Persist client_id, clean_start/session expiry where supported, keep-alive, bounded reconnect setting, initial subscriptions/topic/QoS, connection user-properties, Last Will, and editor draft topic/payload encoding/source/QoS/retain plus named saved messages. Basic credentials reuse RequestSpec.auth username/password; None is anonymous; unsupported auth modes/irrelevant HTTP-only controls must be explicit. Transport TLS verification honors settings with mature verifier APIs, no silent ignore or permissive default. Client-certificate/advanced common TLS functionality remains a separate documented shared module if not implemented here.

Text/JSON draft payloads remain raw strings until execution, and binary uses canonical base64 to preserve bytes. No lossy Unicode conversion or JSON number coercion. Topics and filters use the SDK's MQTT semantics, including wildcard restrictions; reject invalid publish wildcard topics while permitting valid subscribe filters. QoS0/1/2, retain and retained replay must actually work. Clear retained messages via zero-byte retained publish. Subscription/unsubscription acknowledgements and publish delivery events carry actual SDK packet IDs/status/reason codes; distinguish queued/sent/acknowledged, and use SDK handshake state rather than inventing QoS2 delivery guarantees. Preserve incoming topic/payload/QoS/retain/duplicate/properties and server disconnect/error reasons.

MQTT5 connection/publish/subscribe properties and Will delay that the selected SDK supports should be exposed and tested, with explicit version guards for unsupported MQTT3 features. Last Will semantics differ from graceful disconnect: broker publishes it after ungraceful termination; demonstrate using a real broker. Auto reconnect must be bounded, cancellation/owner-safe, use vetted addresses, avoid re-enrolling callbacks or ignoring quota/deadline, and restore subscriptions consistently with clean/persistent-session semantics. Do not advertise reconnect if only a hidden SDK infinite retry loop exists.

## Lifecycle, data scopes and limits

Reuse owner/workspace/request admission/generation/session/retention infrastructure. All networking is through Rust HTTP/IPC, desktop independent/no localhost HTTP listener. Add `mqtt` session summary and typed subscribe/unsubscribe/publish commands/events. Stop must work while creation is pending and after old terminal session, and drop SDK loop promptly on owner/workspace/request logout/deletion. SDK reconnect/address resolution may not bypass network policy or TLS SNI/hostname checks; use public connector injection or minimal documented/licensed SDK patch.

Resolve original selected project/collection/environment/private variables for credentials/client_id/topics/filters/payload/property/will. New UI scope cannot receive old execution updates. Supported pre scripts have explicit MQTT semantics; reject unsupported body/header mutations/phases clearly rather than discarding them. Event scripts/response extraction remain the subsequent shared scripting capability and must not be claimed here if absent. Mask or withhold known-private values in topic/property/status/message bytes and credentials; never persist scope-derived labels into shared drafts. Default native export screens credentials without losing schema definitions; explicit export preserves canonical protocol draft; foreign formats reject unrepresentable MQTT data.

Bound message/property/topic/subscription/saved-message counts, per-message bytes, SDK channel/outstanding QoS packets and reconnect attempts, and reuse current owner4/global64/session lifetime/retention limits. Count actual wire data even if filtered; no unlimited unsolicited/ping traffic. Resource limits should be explicit and stable across native/hosted paths.
