# Atlassian ASAP request authentication

Complete the Postman ASAP provider using pure-Rust jose-rs0.9 (RustCrypto/kryptering) for JWS/key parsing, not custom crypto or token framing. Support RS256/384/512, PS256/384/512 and ES256/384/512, explicit key ID/private key, issuer, audience list, optional subject, default3600second lifetime and original JSON claims. Claims overrides follow Postman priority; missing subject falls back to issuer, missing jti/time fields are generated, protected header contains alg/kid. No symmetric/none fallback or remote key loading.

Accept bounded PKCS8 PEM, RSA PKCS1 PEM, EC SEC1 PEM and percent-encoded/data:application/pkcs8;kid=...;base64,... keys using mature PEM/DER/URL/data parsers. Data URI key ID must match the effective kid. Encrypted keys, unsupported families and RSA-PSS-restricted key types reject rather than lose restrictions. Bound RSA keys2048..4096bits, key DER16KiB, claims64KiB, identity fields4096bytes and audience64entries. Numeric dates are bounded integers; explicit expired dates remain usable for API error testing.

New optional source settings are modular/backward-compatible, environment/folder/workspace-aware and preserve inactive drafts. Resolve claim strings through the existing typed JSON interpolation so quotes/Unicode cannot corrupt JSON; ignore overridden top-level draft fields. Generate at actual finite HTTP/SOAP/GraphQL sends, not save/export, and reissue for same-origin redirects while stripping cross-origin auth. Reject unsupported live protocol/snippet/OpenAPI mappings. Default exports clear keys and screen decoded/encoded/copied source credentials; generated bearer tokens stay out of saved history. Native explicit backups and concrete Postman source mappings preserve source.

Bilingual Radix/CodeMirror editor covers nine algorithms, identity/time/claims/key fields. Necessary validation uses independent Node JOSE verification for all nine families, RSA/PSS and EC format compatibility, typed claims precedence/subject fallback/jti/time, key-URI kid matching/rejections, actual sends/redirects, inheritance/history/privacy/interchange and relevant editor/locale/build checks. No local Docker; full software release remains on main via GitHub Actions after all remaining functional requirements.

## Interchange evidence and boundaries

The official Collection2.1 schema, rechecked2026-10-08, omits ASAP even though Postman Runtime7.56 implements it. The adapter uses the unmodified official schema for ordinary files and an explicitly declared local overlay adding only the known ASAP enum/property for Runtime files. The output filename ends in postman_runtime_collection.json, info._moleapi_runtime_auth_extensions declares asap, and the export result/UI reports a compatibility warning. Unknown helpers and malformed attributes continue to reject. This is a Runtime-compatible extension, not an assertion of official2.1 schema compliance.

Nine captured Rust tokens independently pass Node JOSE verification, including RSA/PSS and raw P-521 ES512 signatures. Five core cases cover algorithm/header/claim structure, key forms/URI kid and family checks, typed claims overrides, actual bearer/JTI/redirect behavior and input rejections. The server environment/inheritance/history case and two format privacy/strict-overlay cases pass. Three editor/catalog checks, strict core/server/formats Clippy, package fmt and production frontend/embedded build pass. Agent-browser sent an ES512 ASAP bearer request to an independent Node JOSE server and verified identity, audience, jti and full JSON body;390px layout does not overflow. English/Chinese screenshots use synthetic credentials only.

Claims override issuer/subject/audience/kid and numeric dates; missing/falsy optional claims follow documented Postman defaults. Subject falls back to issuer; TTL is1..86400seconds, while explicitly supplied expired numeric dates are allowed for401 testing. RSA keys are2048..4096bits. Restricted RSA-PSS DER keys, encrypted keys and HMAC/none/unrecognized algorithms reject. No clock overrides are exposed in UI except claims; source is never signed on save/export. PEM/data URI/percent encoding/DER Base64/LF and CRLF representations participate in existing bounded privacy matching, including unmarked variables and copied content. Native explicit source backups preserve sources; tokens are ephemeral. Additional live/snippet/OpenAPI provider mappings and final graphical platform packages remain separate required work before full release.
