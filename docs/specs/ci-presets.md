# Git-triggered API test presets

Implement a shared pure Rust CI configuration generator, accessible through owned workspace API/native IPC, the hosted/desktop UI and CLI. Generate GitHub Actions, GitLab CI and a Jenkins declarative pipeline that invoke the actual native MoleAPI CLI. Reuse serde_yaml_ng for YAML, shlex for POSIX argument quoting, base64 plus Groovy's built-in decoding for Jenkins literals and regex escaping for exact GitLab branch matches; do not add a shell/YAML/Groovy parser or interpolate user strings into executable templates.

Inputs include remote saved-workspace or repository collection-file source, collection/scenario, environment, saved/temporary dataset, iteration/request filters, explicit notification mode, native report format/language, secret-reference name and optional exact branch names. No actual credential is accepted or embedded. Remote URL validation matches CLI base URL rules; reject control characters/oversized values and GitHub expression delimiters in caller-provided fields. Apply existing selection ownership/IDs/scenario/subtree/notification checks in workspace routes and fence generation to the saved revision. Export only the configuration; never register hooks, modify remote CI jobs or launch requests during generation.

GitHub handles push/pull_request/manual events and archives reports even after failure. Fork PRs in remote mode are skipped because repository secrets are unavailable. GitLab uses push/merge-request/web pipeline rules and always-artifact/report publication. Jenkins polls configured SCM for commits, uses optional exact multibranch selection, binds a configured string credential only in remote mode and publishes reports in post/always. Preserve native CLI failure/empty exit codes. Remove only the reserved .moleapi-ci/report.<format> before each run so failed jobs cannot publish a previous build's report. The runner must already have the CLI installed; installation/binary/Docker packaging remains deferred until functionality is complete.

The workspace UI uses existing Radix/CodeMirror/file saver, English/Chinese strings and account/source/revision/credential/lifetime fences. Local file mode can export the exact owned native workspace snapshot separately through the existing default privacy rules. If a private variable is required in an offline CI collection, users supply it through their chosen saved/exported inputs; generation does not silently include secrets. Necessary evidence: YAML structure/trigger/artifact/secret references, exact quoted argument round-trip with hostile-looking literals, actual generated shell execution against local synthetic HTTP/Postman collection and assertion-failure exit status, owned/revision rejection and UI export/late-result behavior. Full external CI services/platforms/distribution and remaining matrix/release work are separate requirements.
