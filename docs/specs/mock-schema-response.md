# Schema-driven Mock response

Authority: `mock-002` in `docs/FEATURE-MATRIX.md`; saved examples, request matching, scripts, public shares and delay keep their existing contracts. This slice adds an explicit JSON Schema response source to one saved HTTP example. Field-name-aware fake values and authored generation rules belong to `mock-003` and remain open.

## Objective and contract

- An example may store an optional `mock_schema` JSON Schema document. Empty or absent means the existing saved body is returned exactly. When present, the selected example generates a JSON body from that schema for both direct and routed Mock calls. Generation precedes the existing optional script, delay and log path. A script may override the generated body under its existing public-script permission.
- Save-time validation accepts a bounded, self-contained JSON Schema object. The first profile supports `type`, `properties`, `required`, `items`, `enum`, `const`, `default`, `examples`, `minimum`, `maximum`, `minLength`, `maxLength`, `minItems`, `maxItems`, known string formats (`uuid`, `email`, `date`, `date-time`, `uri`), and local references to top-level `#/$defs/...`. Unsupported keywords, including nested `$defs`, unions, composition, patterns, unknown formats and tuple arrays, fail explicitly with a field path; no network or file reference is fetched. Saved OpenAPI response linking is specified separately in `mock-openapi-schema-link.md` and remains an explicit selection.
- Values are deterministic for the same saved schema and example: choose a valid authored `const`, first valid `examples` entry, valid `default`, then first valid enum member; otherwise synthesize minimal values for supported types and bounds. Required object properties are emitted; optional properties are omitted unless they have an authored `default`, `examples` or `const`. Arrays meet the minimum length. There is no call-time randomness, private variable interpolation or network access.
- Bound the schema to 256 KiB, traversal to 64 levels and 10,000 visited nodes, each enum/examples list to 128 values, candidate checks to 256, and generated JSON body to 1 MiB. Cyclic references, unsatisfiable bounds, non-JSON bodies and invalid schemas fail closed before any saved body can leak. Retain the existing 5 MiB saved body validation independently. A generated response defaults to `application/json` only when the example has no enabled Content-Type header. The existing status/header filter applies after generation and scripts.
- The generated body is derived at call time from the current owner-scoped saved workspace snapshot. Public share request digests include the authored schema, and the existing post-delay/share rechecks remain in force. Generic public errors must not reveal schema text or field paths. A full MoleAPI backup preserves the exact schema; the default privacy-screened backup omits it because `default`, `examples` and `const` can contain private values. External interchange formats reject examples they cannot represent rather than silently dropping them.
- The bilingual example editor has an explicit schema-mode control, JSON editor, bounded validation feedback and a generated preview. It preserves a saved static body when switching modes, and its 390px layout remains usable in Chinese and English. A preview uses the same engine as actual Mock calls and does not send a network request to the schema source.

## Evidence and acceptance

- Core old-example compatibility, save-time invalid/ref/cycle/budget rejection, full backup roundtrip and default backup omission; external export rejection where schema cannot be represented.
- Generator fixtures cover primitives, required/optional object fields, arrays, enum/const/default/examples, bounds, local references, deterministic output, unsupported keywords and unsatisfiable constraints. Verify generated output with the repository's JSON Schema validator where its supported dialect applies.
- Real owner HTTP tests cover direct and routed responses, script precedence, status/headers, delay/log, revision changes and owner denial. Public tests cover share digest rotation, script opt-in behavior, generic errors and revocation during a delayed response. Include SQLite, PostgreSQL and MySQL through the existing CI database target.
- Browser save/reload/preview/real request at 390px in English and Chinese, then full frontend/Rust suites, strict Clippy, production/embedded builds, native package and Docker smoke before claiming full platform coverage.

## Project and implementation boundaries

`crates/core/src/models.rs` and `validation.rs` own the additive field and save validation. A focused core generator module owns bounded deterministic JSON generation; `crates/server/src/mock.rs` calls it before scripts. `crates/formats` owns external export policy. `web/src/features/requests/ExamplesEditor.tsx` owns mode editing and preview. Tests live beside those components and in `crates/server/tests/mock.rs` and `mock_public.rs`.

Build: `npm run build` in `web`, then `cargo build -p moleapi-server`. Test: `npm test -- --run` in `web`, `cargo test -p moleapi-core -p moleapi-formats -p moleapi-server` at root. Style: preserve additive `#[serde(default, skip_serializing_if = ...)]` fields and current Rust/TypeScript formatting. Always reject unsupported schema semantics explicitly and keep private schema errors out of public responses; do not add a runtime download, edit vendored code, or change the existing static path when the field is absent.

The full `mock-002` row remains open until representative OpenAPI-linked response schemas, composition/union/tuple support, wider dialect coverage and platform gates have evidence. `mock-003` rule and field-name data generation remains a separate requirement.
