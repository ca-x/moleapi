# Scenario conditions, branches and bounded loops

Extend the existing saved-scenario module with optional JavaScript condition expressions (4KiB), repeat counts (default1,1–1000), and typed true/false successors (next enabled step by default, explicit step ID or end this data iteration). Conditions run before request pre-scripts against snapshot pm variables/data and the previous actual response, using the existing mature QuickJS application worker. They must synchronously return a boolean; exceptions, invalid values, promise work and limits fail the run with fixed diagnostics. No new expression parser or dynamic host API.

Condition updates, request mutations, tests, logs and execution controls are discarded. Only the host-observed boolean and privacy taints leave condition evaluation. False conditions skip all request phases/network/history, produce a marked report item, and choose the false successor. True conditions execute the request. Script setNextRequest/stop retains precedence; otherwise repeat the step and re-evaluate its condition, then choose its true successor. Explicit backwards edges implement multi-step while loops, with existing1000-step/300s/cancel/owner/capacity quotas counting every visit including false conditions. Repeat counters reset on explicit jumps; stop ends the current data iteration only.

Validate branch references within the scenario and reject enabled edges to disabled/missing steps. Explicit target identity remains stable on reorder. Default privacy clears and disables conditions changed by credential screening, preserving importable references; explicit backups preserve exact controls. Old servers discarding controls cannot acknowledge sync.

Expose condition, repeat and true/false destinations through existing bilingual Radix controls, with target labels using step position/name and deletion clearing outgoing references. Show condition-skipped results and condition errors distinctly. Necessary checks: actual extraction-dependent branching, false no-network, fixed repeats and backwards loop exit, condition mutation isolation/invalid/timeout, ID/reference/disabled validation, report/backup privacy, source preservation, owner/cancel gates, targeted UI/catalog/type/build and worker regressions only. Parallel/nested grouping/scheduling/durable reports remain subsequent required scope.
