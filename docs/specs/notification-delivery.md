# Owned notification channels and durable delivery

Implement monitoring-005/integrations-001/002 foundations for scheduled run outcomes, preserving remaining workspace collaboration event/CI/manual-run integration scope. Reference sources read with agent-browser: Apifox notification-targets/events (WeCom,DingTalk,Feishu,Teams,Webhook,Jenkins,Email) and Postman integration/PagerDuty pages (Slack,Teams,PagerDuty monitor integration). Distinguish provider HTTP success from accepted application receipts. No claim of bot-app installation/OAuth/provider end-to-end validation.

Owned targets define name/kind/enabled/outcome filters/change-only/locale. Private endpoint URLs, signing/routing tokens and SMTP credentials live in a separate owned workspace credential document and never return through metadata/ledgers. Public responses expose origin/SMTP settings and secret-presence flags. Updates keep omitted secret fields, allow explicit replacement/clearing and use config CAS. Match existing owner/workspace vault storage; do not falsely label plaintext-at-rest documents as encrypted. Workspace deletion cascades all target/credential/delivery rows.

HTTP transports reuse checked/pinned core networking with redirects/proxies disabled, bounded timeout/response body and fixed diagnostics. Payloads support generic signed Webhook (HMAC-SHA1), Slack, Teams Workflow Adaptive Card, WeCom, signed DingTalk/Feishu, Jenkins Bearer and PagerDuty v2 trigger/resolve with stable dedup key. Mature hmac/sha1/sha2/base64 own cryptographic primitives. Email uses Lettre0.11.23 MIME/mailbox/SMTP and TLS; prevalidate/pin destination IP while TLS retains original hostname. No custom SMTP parser, arbitrary process or unvalidated private networking.

Schedules select up to20 owned target IDs. Completion/expired-lease events enqueue delivery documents transactionally with occurrence state. Events include only fixed status/counters/time/report ID and privacy-screened names; no live bodies/logs/variables or channel secrets. Outcome/change filters suppress unsolicited repeated notifications. Delivery IDs and idempotency headers remain stable across bounded retries. A router-owned weak engine claims sending leases atomically, loads a matching enabled channel version and uses limited concurrency. Retry transient failures with bounded backoff; permanent rejections fail without looping. Network timeouts/crashes may duplicate accepted external messages; no exactly-once claim. Channel deletion/disable/replacement cancels obsolete pending work. Keep bounded delivery records for owner inspection/retry.

Bilingual Radix UI configures provider/SMTP, filters and credentials, selects targets for schedules and displays sanitized delivery states. Only local synthetic HTTP/SMTP fixtures send messages during implementation checks. Necessary checks: actual queued scheduled delivery, provider envelopes/signatures/receipts, SMTP MIME/send fixture, retry/permanent rejection, private network admission, ownership/secret withholding/version fences/cascade, and scoped UI/catalog/type/build. Broader integrations/distributed runners/remaining feature matrix and final unified review/main release stay open.
