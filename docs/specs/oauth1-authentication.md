# OAuth 1.0 request signing

Continue auth-006 coverage using oauth1-request 0.6.1 for OAuth protocol options, serialization and normalization; RustCrypto owns SHA/HMAC/RSA. Source lives in an optional boxed OAuth1Auth configuration and remains compatible with older workspaces. This module signs finite HTTP/SOAP/GraphQL query/mutation requests after actual URL, headers and body materialization. Live protocols reject explicitly.

Fields: consumer key/secret, token/secret, private PEM key, HMAC-SHA1/256/512, RSA-SHA1/256/512 and PLAINTEXT, header/query/form-body placement, realm, optional nonce/timestamp/callback/verifier, OAuth version inclusion, optional non-form body hash and inclusion of empty application parameters. Defaults follow RFC signing (empty application parameters included). Postman source options are mapped explicitly; standard OAuth fields with empty optional values are omitted.

SDK integration must preserve duplicate and Unicode query/form parameters and RFC3986 encoded sorting, not SDK raw-string sorting. Encode dynamic keys twice for the SDK Sign key contract, sort by once-encoded name/value, pass raw values to the SDK serializer. SDK remains responsible for merging generated OAuth fields. Never parse OAuth headers manually. Native source exports preserve configuration; default exports clear credentials and screen copied values across parent/variable/request source. Generated signatures and tokens are private history values.

Signing uses the final method and canonical base URI (no query or fragment, normalized host/default port). Query + application/x-www-form-urlencoded body contribute parameters; other bodies contribute only optional body hash, computed over exact transport bytes. OAuth-owned source parameter collisions reject. Header collisions reject. Body placement requires an actual form content type. Same-origin redirects re-sign actual hop/method/body; cross-origin redirects disable signing and strip generated private data by retaining only source request URL/headers/body. Existing downgrade/network policies remain enforced.

Bounds: bounded source fields, at most 2048 signing parameters, bounded generated authorization/form output, and RSA keys validated at 2048..4096 bits. RSA parse/sign errors reject before transport; no sentinel signatures sent. Inactive provider/private-key drafts do not resolve unused placeholders. Synchronous RSA execution retains an explicit key-size bound, not a claimed CPU sandbox.

Necessary evidence: published RFC5849 vector; independent Postman OAuth library oracle for Unicode/duplicate/encoding/form/body-hash and algorithm families; actual HTTP header/query/body execution and redirects; inherited environment signing/private history, native/Postman source/privacy and UI controls. Token request/access exchanges and browser authorization automation are separate required follow-up capabilities, not fabricated as completed by request signing.

## SDK adapter and evidence

`methods.rs` implements documented SignatureMethod/Sign extension points. SDK-generated base-string events feed RustCrypto HMAC-SHA256/512 or RSA PKCS1v1.5 SHA256/512, with explicit RSA errors checked before transport. Standard HMAC-SHA1/RSA-SHA1 use SDK implementations. PLAINTEXT wraps its SDK signature once more with RFC3986 encoding because the SDK returns an already-encoded key with an unescaped ampersand while its Authorizer expects an encoded whole signature. Nonce and timestamp remain present for OAuth1.0a/Postman compatibility. A signature decorator records both transmitted encoding and decoded signature for private history handling, including PLAINTEXT key combinations.

`verify_oauth1_vectors.cjs` uses the independent node-oauth1 implementation used by Postman Runtime. Its synthetic 2048-bit fixture key is test-only. All 14 fixtures reproduce without invoking MoleAPI. The published RFC5849 example separately verifies its well-known HMAC-SHA1 signature. Necessary core/server/interchange/editor/catalog checks and strict Clippy/fmt/build pass; real embedded browser header and form sends succeeded. RSA keys2048..4096 bits and normalized application signing parameters256KiB/2048 rows are explicit limits. SDK authorizer output never includes application parameters in the generated OAuth-only form; original body bytes remain unchanged before appending those fields.

Postman maps Header and Automatic source modes, seven signature methods, version1.0 and concrete flags. Native explicit query/body modes reject external conversion because Postman changes placement according to method/body. Templated boolean flags, custom version and disabled header encoding retain original Postman source and warn with execution authentication disabled until reconfigured. Request snippets/OpenAPI dynamic-auth mappings remain unsupported explicitly. Separate OAuth1 request/access token exchanges, automatic browser callbacks and private token-vault management remain incomplete.
