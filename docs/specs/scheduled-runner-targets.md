# Scheduled runner targets and management

Continue the existing self-hosted runner module. Add bilingual hosted management to register, rename, enable/disable, queue selected saved collection/scenario/environment/dataset work, inspect task status, cancel tasks and open reports. Queries and asynchronous writes are fenced by account, credential and workspace. Queueing saves dirty workspace changes first and uses the returned canonical revision. Offline mode shows the hosted requirement without calling hosted-only APIs.

Schedules accept an optional `runner_id`; absent/null retains existing local/server execution. Validate enabled owned runners before saving or manually queueing. On each due occurrence, atomically insert one single-attempt runner task with the current saved workspace revision and persist its ID in the schedule job. Dispatch must share existing selection, quota, ownership, revocation and report handling. Acquire the account lock before workspace locks when touching runner tasks. Never hold a transaction during remote execution.

Persisted runner jobs are reconciled across server instances and restarts. Queue wait has no arbitrary execution deadline; agent lease expiry follows existing single-attempt rules and never automatically replays network effects. Reconcile terminal results into schedule history/report links and notifications once. Schedule cancellation, configuration edits and deletion cancel the associated queued/leased task atomically. Do not execute runner-targeted schedules locally or silently fall back when a runner is unavailable.
