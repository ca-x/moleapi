# Persistent schedules and leased executions

Implement monitoring-001/002/003/004/005 foundations with owned named collection/scenario schedules, enabled state, cron/timezone, canonical environment/dataset and iteration references. Reuse croner4.0.1 and chrono-tz0.10.4 (5/6 fields, optional seconds, IANA timezones) and the existing runner/reports. No custom cron parser, extra transport or plaintext copied variable inputs. Preview next occurrences. UI states that enabled hosted tasks survive logout and desktop tasks require the app to stay running.

Persist configurations and running/queued/last execution state as schedule documents, with a separate config revision for editor CAS. Document revision stores the indexed next wake timestamp (cron, queued or lease expiry; disabled idle uses i64::MAX). Add a kind/revision index via a new SeaORM migration without changing the initial migration. Workspace deletion cascades through existing ref IDs. Job ledgers use sched-run documents with owner/workspace and safe schedule UUID prefix; retain the latest100 per definition.

A weakly owned engine lifetime attached to the router starts a bounded periodic scan and is canceled when its router lifetime ends. Tasks own AppState clones but never keep the lifetime guard alive. Global capacity is bounded and normal runner capacity still applies. DB transactions lock workspace before schedule, re-read current state and claim one job with an ID/600s lease before sending. Advance the scheduled cursor from current wall time rather than replaying every missed occurrence. Active jobs do not overlap the same schedule; expired leases become interrupted records, not retries of uncertain network effects. Future occurrences proceed. Finish is fenced by matching job ID and preserves later config edits. Stop/drop cancels active work; pending/running metadata remains recoverable. No exactly-once side-effect claim under process failure or severe clock skew.

Authenticated CRUD/list/preview/queue-now/cancel/history endpoints verify owner and workspace. Disabled tasks can be manually queued without being enabled. At most one queued manual occurrence per definition. Config edits cancel obsolete active/pending work, disabling prevents future cron runs. Network admission is the shared runner policy; no host-side custom executables. Scheduled execution checks that hosted owners still exist, without retaining a session token. Logout cancels in-flight runs through existing owner fencing, but enabled definitions remain active for later occurrences.

Persist only fixed outcome/error codes, counters, timestamps and saved report IDs. No live response/body/log/variable storage in job state.
