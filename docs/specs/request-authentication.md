# Request authentication

Authority: complete feature matrix auth-001..017, user instruction to continue to full coverage using mature Rust crates. Existing No Auth/Basic/Bearer must remain compatible. Add API Key header/query, JWT generation/signing and Digest challenge handling in a modular core authentication provider; mature jsonwebtoken11.1.0 (RustCrypto/PEM) and digest_auth0.3.1 own cryptography/challenge encoding. Do not write cryptographic or Digest parsers.

Typed optional auth settings preserve old JSON. API Key: name/value/location. JWT: algorithm, raw/base64 HMAC or explicit private PEM key, original JSON claims, optional kid, configured prefix/name/location and optional timestamp/TTL claims. Only explicit supported signing algorithms; no algorithm none, no hidden filesystem key loading. Original claims parse/resolve through mature serde and bounded per-value interpolation, preserving quoted values and typed claims. Never sign during save/export or silently produce an unsigned token when keys are withheld. Digest reuses username/password, authenticates only after401 challenge, signs actual method/path/query/byte snapshot (including auth-int), bounded retries/stale handling within original deadline. Credentials never reattach after cross-origin redirects; redirects retaining signed tokens/query values must retain existing ownership/network protections and not leak selected API keys.

API Key/JWT placement works in shared checked HTTP/header and live handshake preparation where the protocol supports those transports; incompatible database/MQTT/TCP mechanisms must reject rather than silently ignore. Generators/exporters preserve native source; external mappings are verified or explicitly rejected. Default export clears API values/signing keys and screens copied known secrets including decoded forms. Ephemeral generated tokens/digest answers cannot persist in history/default export/logs. Bilingual modular editor, environment/template support and stale-owner/callback fences follow existing UI conventions.

Collection/workspace/folder inheritance, OAuth1/2/PKCE, AWS/Hawk/NTLM/EdgeGrid/ASAP and related advanced credential management remain required capabilities; these must be implemented in subsequent tasks before calling the auth module complete. This slice does not redefine the complete goal.
