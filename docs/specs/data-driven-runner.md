# Data-driven collection execution

Extends execution-extensions.md and FEATURE-MATRIX testing-006/010/011/012. Full scenario branching, durable reusable datasets and scheduled/distributed execution remain separate required capabilities. User authorization is to implement remaining functionality before the next unified review; no intermediate review/approval gate is added.

Implement ephemeral CSV/JSON dataset import/preview, configurable collection iterations, typed read-only pm.iterationData, pm.info iteration/count, per-iteration results, bounded reports and explicit cancellation in hosted/native shared routes. Keep current single-run payloads and response fields compatible. CSV parsing uses csv1.4.0; JSON uses serde_json, never custom lexical parsers. Source paths/URLs are not loaded by the server.

Dataset: at most1 MiB source,100 nonempty object rows,100 fields per row,64 KiB encoded value,50k nodes/64 nested levels. CSV has a header row with unique nonempty names and uniform row widths; values stay strings. JSON preserves numbers/booleans/null/arrays/objects for scripts; interpolation uses existing stored strings/JSON encoding. Preview is owner/workspace bound and does not persist sources or values.

Runner: optional dataset plus optional iteration count. Omitted count uses all dataset rows or one run; explicit count selects the first N rows and may not exceed dataset rows. Without a dataset, iterations repeat the collection with existing data overrides. Temporary overrides retain their existing higher priority. Environment/project/temporary and collection updates chain across requests/iterations within the run; canonical workspace stays unchanged. Replace only current iteration data and metadata. Capture all dataset leaf/private values for history redaction, including nested JSON copies across iterations. Data maps are read-only; script getters return copies.

At most100 iterations and1000 request executions,300s run deadline, bounded8 MiB returned report with explicit omitted-response counts. Reject invalid datasets/options before network calls. Reuse checked HTTP/script/body/auth/cookie execution and scoped job cancellation. Cancel/logout/workspace deletion stop pending work, without reporting unexecuted steps as successful. Check owner/workspace admission before each step. Result records add zero-based iteration and summaries; the original results/passed/failed/elapsed_ms remain available.

Modules: crates/core/src/datasets.rs parses/validates typed data; variables.rs carries additive iteration metadata; script-runtime pm adapter exposes read-only APIs; server runner owns lifecycle/execution/reporting; UI dataset editor/preview and runner state use existing Radix/CodeMirror/file pickers. Requests/scripts share existing mutation/privacy behavior. User-authored sources are never executed as programs and datasets do not get stored implicitly.

Necessary checks: quoted/newline CSV, typed/nested JSON and limits; actual row interpolation and scripts against a loopback fixture, hierarchy mutation chaining, history privacy, ownership and cancellation; frontend preview/import/source/owner fences and iteration-labelled result rendering. Commands: CARGO_TARGET_DIR=/tmp/moleapi-grants-target cargo test -p moleapi-core datasets; cargo test -p moleapi-script-runtime --test runtime iteration; cargo test -p moleapi-server --test data_runner; node web/node_modules/vitest/vitest.mjs run the changed runner tests; scoped Clippy/typecheck/production build. Do not rerun unrelated passing suites.
