# Saved reusable test scenarios

Extend testing-006/007/008 with persisted named scenario definitions in additive WorkspaceData.scenarios. Each scenario selects a root collection and an ordered list of uniquely identified request steps (request ID, label, group and enabled). References point to canonical saved requests within the root subtree, not copied requests. Repeated request references are valid. All definitions use existing workspace CAS/storage/version/sync and native backups. Old documents omit scenarios and retain current collection-run behavior.

Run accepts optional scenario_id, checks its root matches collection_id, and executes enabled steps in saved order through the existing finite HTTP runner, variables, datasets, scripts, extractions, cancellation and ownership gates. Reports identify scenario and step/group without leaking private metadata. Script jumps to request ID/name require a unique enabled occurrence; repeated occurrences cannot silently select the first. Empty enabled plans fail before execution. Limits:100 scenarios,1000 total saved steps, IDs128 bytes, names256 bytes, descriptions4096 bytes; the existing1000 executions/300s/report quotas remain.

UI provides named scenario creation/edit/delete, request selection, repeated steps, labels/groups, enabled state and keyboard-accessible move-up/down controls with existing React/Radix components. Scenario selection runs with the existing active environment and dataset options. Keep pending editor actions fenced to current owner/workspace. Explicit save follows existing CAS; no shared extraction values are auto-persisted. Frequent reorder controls do not animate.

Necessary validation: persisted/reordered/repeated/disabled execution with actual response transfer, wrong-root/missing-reference/owner failures, unique-jump behavior, default backup privacy/explicit retention, old-server sync source-loss refusal, editor and scoped type/catalog checks. Conditional/loop/parallel blocks, scheduled runs, durable reports and the rest of the feature matrix remain required follow-on work before unified review/release.
