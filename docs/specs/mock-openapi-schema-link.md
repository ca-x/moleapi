# Linked OpenAPI response Schema for Mock

Authority: `mock-002` and `mock-003` in `docs/FEATURE-MATRIX.md`, `docs/specs/mock-schema-response.md`, the saved OpenAPI specification/request relationship, and the existing public Mock capability contract. This slice lets a saved HTTP example select a response Schema from its workspace's OpenAPI 3.0/3.1 source without copying the source text into the example.

## Contract

- An example gains an optional `mock_schema_link` with `specification_id` and an exact JSON Pointer to a response media Schema under `/paths/{path}/{method}/responses/{status}/content/{media}/schema`. The request's existing `specification_id` must equal the link's specification ID; the specification must have `kind=openapi`. A request may have no `operation_id`, so path/method selection is explicit. A link and inline `mock_schema` are mutually exclusive; a saved static body is retained when switching modes.
- The pointer must identify one actual HTTP operation whose method matches the saved request and an explicit numeric 200–599 response matching the example's saved status. The media type must be JSON (`application/json` or `*+json`). An enabled example Content-Type must match that selected media; otherwise saving rejects. The editor lists selectable response paths/status/media from the saved specification and sets the saved example status and any enabled Content-Type to the chosen response. It shows the chosen source and schema origin, and offers a clear switch back to inline/static mode. It reports missing, ambiguous and unsupported selections before save. JSON and YAML OpenAPI source are treated equivalently.
- Before changing an example, the editor calls owner-scoped `POST /api/workspaces/{id}/mock-schema/validate` with `request_id`, `specification_id`, exact `pointer` and `expected_revision`. The route checks the current saved source under the eight-slot schema worker, returns only method/status/media on success, rejects foreign owners or stale revisions, and reports unsupported schema constructs without returning source bytes. The selector treats specification ID and pointer together as its identity, so switching specifications cannot make an old link appear current.
- Resolve local response and Schema `$ref` values only inside the same saved source. Reject external URLs/files, cycles, unresolved pointers, unbounded traversal and unsupported schema constructs. Translate local `#/components/schemas/...` refs to the core generator's top-level `$defs` profile, preserving referenced values and authored `example`/`default`/`enum`. For OpenAPI 3.0 `nullable` and OpenAPI 3.1 `type: ["null", T]`, choose non-null `T` when supported. Known `format` values `uuid`, `email`, `date`, `date-time` and `uri` generate valid fixed values; unknown formats reject explicitly. Do not fetch a runtime tool or remote source.
- Parse and validate a linked source at save time under the existing 5 MiB specification limit, but cache each distinct specification parse and response pointer within that workspace validation. At most 256 linked examples may belong to one workspace. Bound reference traversal to 64 levels and 10,000 visited nodes, then use the existing 256 KiB generated-schema, 256 candidate-check and 1 MiB body limits. Runtime generation stays on the current eight-slot blocking path and reads the owner-scoped current workspace snapshot. A changed/deleted specification or broken pointer fails closed; no saved static body is served as fallback.
- Public shares bind to both the saved request and exact linked specification source digest. Editing the source makes an old share stale until explicit rotation, including across instances and during delayed calls. The public error remains generic and never exposes Schema text or source paths. Full MoleAPI backup preserves the link and source; default privacy backup clears links when it screens source content; external formats reject unrepresentable linked Mock behavior.
- The existing direct, routed, script, delay and call-log behavior remains shared. A linked Schema generates body before script; public script execution still requires the separate opt-in. A response with no enabled Content-Type uses the selected JSON media type.

## Acceptance evidence

- Core save and generator fixtures: JSON/YAML OpenAPI 3.0/3.1, operation with and without `operationId`, response/status/media/pointer mismatch, local response and component refs, supported formats/nullable, unsupported/external/cyclic refs, source edit/removal, source and output budgets, and old example JSON compatibility.
- Real hosted/local direct and routed calls, owner denial, script override, delay/revision fencing, default/full backup behavior and external export rejection. Public capability tests prove the exact linked source digest, rotation/revocation, no token/schema leakage and cross-instance source-edit fencing. Existing SQLite/PostgreSQL/MySQL CI target executes linked-source owner and privacy cases.
- English/Chinese browser: choose a linked response, save/reload, preview and call the actual route at 390px without document overflow; inspect status/media and generic unsupported errors. Run full relevant Rust/frontend suites, strict Clippy, frontend then embedded-server build, Docker and native package checks before claiming platform support.

## Structure and boundaries

`crates/core` owns the additive link model, saved-workspace validation and bounded normalization into the current generator input. `crates/server/src/mock.rs` uses the current owner-scoped workspace and generation worker. `crates/server/src/mock_public.rs` extends capability digest input only when a request has linked examples. `crates/formats` preserves or rejects links. `web/src/features/requests/ExamplesEditor.tsx` receives saved specification metadata from `RequestEditor.tsx` and owns the explicit selector.

Build: `npm run build` in `web`, then `cargo build -p moleapi-server`; test: `npm test -- --run` in `web`, `cargo test -p moleapi-core -p moleapi-formats -p moleapi-server` at root. Preserve existing Serde defaults and workspace CAS, do not edit vendored generators, download schemas, or use an unbounded parser/resolver. Composition/union/tuple generation, schema-name fake rules and full `mock-002`/`mock-003` matrix claims remain open until separately verified.
