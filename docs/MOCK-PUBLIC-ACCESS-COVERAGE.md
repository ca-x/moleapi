# Public Mock access coverage

Scope: hosted portion of `mock-011`, `docs/specs/mock-public-access.md`, branch `feat/mock-public-access`. Owner-authenticated `/api/mock` and `/api/mocks` endpoints remain private. Hosted sharing is explicit per saved HTTP request; an offline native IPC router does not offer a public listener.

The owner creates a 1–90-day share with a 256-bit random URL token. The database stores only a SHA-256-derived lookup key and owner/workspace/request metadata; list responses omit the token and creation/rotation shows it once. At most 20 active shares belong to one workspace. Rotate atomically disables the old token, revoke removes it, and workspace deletion cascades it. Default and full MoleAPI backups omit share capabilities. The share binds to the exact saved request digest: an edit makes the old URL stale until explicit rotation; deleting a request revokes its shares in the workspace update transaction, so recreating the same ID/content needs a new share. Dynamic Mock scripts require a separate opt-in because they can read workspace data.

Public direct and routed calls use the existing selection, response, delay and owner-private log engine with a one-request filter. Anonymous callers cannot use the original private routes. The public script URI omits the token; incoming Authorization, Cookie and sensitive fields retain the existing filter. Missing, expired, revoked and stale capabilities return a generic 404. The share is rechecked after scripts/delay and once more after log persistence before returning bytes, including across two server instances. A 32-call admission cap returns 429 before excess matching work. Public replies disable caching/referrers and allow credential-free cross-origin calls.

Local evidence: eight hosted integration cases cover create/list/rotate/revoke, other-owner isolation, digest-only storage and backup privacy, direct/routed request scoping, explicit dynamic permission, generic script-error privacy and token-free script URI, expiry and pruning, changed and byte-identically recreated request IDs, non-HTTP rotation refusal, cross-instance revoke during delay and 33rd-call saturation. The existing `database.rs` suite includes a create/rotate/delete lifecycle for configured SQLite/PostgreSQL/MySQL; both SQLite database cases passed locally and PostgreSQL/MySQL require branch CI. Existing Mock 14 and Mock-call-log 5 integration cases passed after the routing refactor. After the review fixes, the full server test suite passed with its pre-existing external fixture ignores and the unprepared Java catalog case excluded; the eight focused share and two database cases also passed. The bilingual frontend suite passed 365 tests, and production frontend/embedded server builds plus strict all-target server Clippy passed.

Actual 390px hosted browser: an imported HAR request's static example was shared and called anonymously with HTTP 200, while its old private Mock URL returned 401. The editor initially offered a routed URL without required saved query parameters; this was reproduced as a 404 and fixed. Requests with saved query conditions now show the working direct example URL plus a query warning. After reload the raw token disappeared, rotation produced a new one-time address, and revocation made the public URL return 404. Chinese and English controls rendered at document/viewport width 390px. Moving share management into a bounded dialog exposed the copy/revoke controls above the short mobile request pane; a focused WCAG audit of the dialog reported zero violations after neutral-button contrast fixes.
