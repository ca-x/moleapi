# Saved run report coverage

Completed and stopped collection/scenario runs now persist immutable, owner/workspace-scoped reports alongside a lightweight summary document. Models record the source workspace revision, collection/scenario/environment/dataset references, UTC start/finish times, iteration/request outcomes, actual method/status/timing/size, repeat/group/parallel identity, assertion counts, bounded diagnostics and stop reasons. Live results carry report_id after success or an explicit report_save_error while retaining results after a storage failure.

Per-item outcome/assertion counts and actual scripted method changes are recorded before live response trimming. Omitted response details therefore do not invent passing results or lose assertion totals. Stored reports exclude live bodies, headers, logs, request mutations, variable setters and dataset source text. Canonical source privacy reuses the mature export projection—including inactive environments/datasets/inherited authentication—and runtime privacy reuses the execution redactor. Uncertain execution errors/failed scripts withhold diagnostic text. Matching known private copies are screened; this is not universal inference of arbitrary unknown secret encodings.

## Persistence and lifecycle

The shared SeaORM document storage supports the configured SQLite/PostgreSQL/MySQL backend without a new database table. A transaction obtains a no-op workspace-row write lock, checks workspace existence/source revision lineage, inserts the full/summary records and trims to the latest100 reports. Ordinary edits retain version lineage and allow older-source reports; deletion/recreation clears it and fences stale saves into the recreated workspace. No canonical workspace data/revision/update timestamp is changed by saving a report. Owner epoch changes suppress late persistence. A user-canceled run with an extant owner/workspace retains its stopped report. Reports survive restart and source interface edits/deletions; deleting a workspace cascades through existing owned document deletion.

Artifacts are capped at1000 steps/4MiB with1MiB total diagnostic text,100 diagnostic entries per step and bounded strings. Failed assertions are retained first; missing whole diagnostics are counted. Privacy/field-limit withholding uses explicit markers. Response/history linking is now available; see [response-link evidence](REPORT-RESPONSE-COVERAGE.md). Optional detailed payload exports remain unfinished.

The authenticated API lists lightweight summaries using timestamp/ID seek cursors, exposes full lookup, one/all deletion and format export, and verifies both owner and requested workspace. Pages contain1–50 summaries (default20) instead of loading full report payloads. Retention/deletion keeps full/summary documents paired. Operational reports belong to the serving instance; workspace definition synchronization does not yet synchronize report artifacts.

## Export and interface

JSON uses serde_json, CSV uses mature csv1.4.0 with formula-leading text protection, JUnit uses quick-junit0.8.0, and standalone English/Chinese HTML uses Maud0.27.0. HTML/XML escaping and CSV quoting are upstream-owned. JUnit preserves passed/failed/skipped occurrences and adds an error case for stopped or empty runs, so canceled/incomplete runs cannot appear as an empty successful CI result. HTML fixed labels follow the selected locale; user data retains its original language. Exports are bounded to16MiB and contain only the stored projected artifact.

The React/Radix testing page lists/refreshes/deletes/pages reports, opens paginated/filterable step/diagnostic details, links failures to a still-existing canonical interface and downloads through the existing fenced browser/native file saver. Account/workspace/report/language fences discard late data or picker writes; closing a report invalidates its export. Frequent report navigation/filtering adds no motion. Live save success/failure is visible; deleted source requests do not invalidate the historical report.

A real SQLite lineage test covers normal edits versus deletion/recreation fencing. Export tests round-trip upstream JUnit and CSV, protect formula input, verify bilingual HTML escaping and reject false empty/canceled/conflict success.

Frontend tests cover details/current failure location, report downloads and file-saver identity fences, closing a dialog before export completion, existing collection-flow selection, bilingual catalogs, TypeScript and production build. Scoped Clippy passed; only changed paths were repeated after corrections/new code. Database/platform matrix and rendered/native OS verification remain in the final unified phase; this feature does not claim final release readiness.

Report sharing/comparison/trends, payload-inclusive exports, artifact synchronization, crash-recoverable jobs, scheduling/distributed runners, richer parallel/visual orchestration and all other unfinished matrix capabilities remain required before unified review, main-branch merge/cleanup and the new Actions release. No local Docker or package/release build was performed.
