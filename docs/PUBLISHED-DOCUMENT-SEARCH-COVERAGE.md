# Published document search coverage

Scope: the anonymous public-site part of `documentation-009` described in [published-document-search.md](specs/published-document-search.md). Private workspace search is documented separately in `WORKSPACE-DOCUMENT-SEARCH-COVERAGE.md`; this profile never reads that private search source.

The public page searches only the already fetched immutable Markdown snapshot. A literal, bounded Unicode-insensitive AND query matches published titles, folder labels and exact Markdown source; results preserve publication order. Empty query restores every published document. A nonempty no-match query shows an explicit status and leaves the selected article in place. Selection is a keyboard-operable button, does not change the public URL and does not request another API resource. Query/result text is not persisted or sent to a server. The anonymous page has an English/Chinese language switch and retains its site title when the locale changes.

Local evidence: focused pure and page tests cover Unicode normalization, literal metacharacters, AND terms, title/folder/source matching, stable order, empty/no-match state, anonymous one-fetch behavior and language switching. The integrated frontend suite passed 417 tests across 112 files; TypeScript and the production 46-chunk cycle verifier passed, followed by an embedded server build. In a real anonymous 390 px browser, a three-document snapshot filtered to `Operations guide`, Enter opened its article, no-match retained it, and switching Chinese/English changed the labels without changing the site title. The page fetched its public snapshot once during the search flow, kept document width at 390 px, and did not display the private sentinel. axe found zero violations and zero incomplete checks. The parent's root-folder save fix was also rechecked in the hosted owner browser: a new root document saved cleanly without a reload, then all three nonprivate documents were published in one snapshot.
