# Markdown document resource coverage

Scope: the editable workspace resource profile of `documentation-001`, specified in [markdown-document-resources.md](specs/markdown-document-resources.md). It does not publish a documentation site or close the full documentation module.

Workspaces store up to 256 named Markdown documents, optionally assigned to an existing collection folder, with a 256 KiB source limit and 2 MiB aggregate cap. Old workspaces default to an empty list. The Documents page can create, select, rename, edit, move and delete with confirmation; removing a folder returns its documents to the workspace root. The existing workspace revision CAS, owner scope, native offline data and sync carry the documents. A simulated old server that drops the new field cannot acknowledge the native sync baseline.

The preview uses React Markdown 10.1.0 and remark-gfm 4.0.1; CodeMirror Markdown 6.5.2 powers source editing. Raw HTML is ignored, image syntax shows alt text without fetching remote resources, and only explicit HTTP(S)/mailto links become links with `noopener noreferrer`. Default MoleAPI backup keeps document metadata but clears private sources; an explicitly nonsecret document is screened through the shared known-secret matcher. Full backup restores exact source. Postman/OpenAPI/HAR exports reject documents until an exact mapping exists.

Local evidence: core validation tests covered old JSON, duplicate IDs, invalid titles/folder references, per-document and aggregate limits. Formats tests covered default/full privacy, budget exhaustion and external rejection. A real hosted router saved and reloaded an owned document, denied a foreign account, rejected a dangling folder without changing revision and preserved an edited source. A CLI process imported a native document and exported a screened default and exact full backup. The mixed-version sync fixture rejected an old server that dropped documents while preserving the local original. The full core/formats/server/CLI Rust suite, 378 frontend tests, TypeScript, scoped strict Clippy and rustfmt passed. After the private flag was normalized in server JSON, the affected core/formats/hosted/CLI cases passed again. The final production frontend build, ESM chunk verifier and embedded server/CLI builds passed.

At 390px, the embedded English browser created a private document, assigned it to a folder, edited and saved exact multiline Markdown, then reloaded and previewed headings, emphasis and a safe link. The preview rendered neither raw script nor an image element, and made no request to the image host. Chinese controls displayed after switching language; document width remained 390px. axe reported zero violations and one incomplete contrast analysis because the background could not be inferred for a few elements. After the server serialization fix, a title edit and save immediately returned the document page's button to its gray disabled state. A production-only static import cycle appeared after adding the Markdown editor language; its actual blank-page failure was reproduced. The Vite chunk boundary was repaired and the production build now runs a static ESM chunk-cycle verifier, which failed on the old bundle and passed on the repaired 46-chunk bundle.

Independent review found that switching away from an invalid draft could re-enable Save and that Ctrl/Cmd+S bypassed the page button. The Documents page and all workspace save entry points now share validation of every document title, UTF-8 source size and their 2 MiB aggregate. Errors name the offending document; invalid drafts cannot reach the save API. Cross-document, aggregate and controller regressions pass; the complete frontend suite has 381 passing tests, and TypeScript, production build and 46-chunk cycle verification pass on this fix. Independent re-review found no remaining high-confidence issue.

Open: fixed-head three-database/Docker/native package gates, installed smoke, internal cross-resource links, attachments/remote images by explicit policy, document search, versioned publication, access controls, custom domains/themes, analytics and the other documentation rows. `documentation-001` remains a bounded profile rather than full product parity; the 395-item goal remains open.
