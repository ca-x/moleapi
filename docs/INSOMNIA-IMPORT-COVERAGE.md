# Insomnia V4 JSON import coverage

Scope: the finite `interchange-014` profile in [insomnia-v4-import.md](specs/insomnia-v4-import.md). The shared `format=insomnia` converter serves the hosted owner-scoped import route, standalone CLI and bilingual import dialog. It creates one workspace; import never executes captured requests automatically.

| Source | Behavior |
| --- | --- |
| V4 JSON, one workspace, up to 5 MiB | Optional `_type: export`; one explicit workspace or the implicit `__WORKSPACE_ID__` root used by request-only exports. Exact source retained for full MoleAPI backup. More than one workspace, duplicate IDs and unsupported resource kinds reject atomically. |
| Up to 1,000 HTTP requests, 1,000 folders, 100 environments | Preserves folder ancestry and request order, rejects dangling/cyclic/deep parents and non-HTTP resources. |
| HTTP(S) URL and parameters | Rewrites only known base-environment `{{ _.name }}` URL tags to MoleAPI variable syntax and validates the resolved URL in every imported child environment. The URL query is the wire authority; a matching parameter list is not duplicated, while contradictory or still-present disabled parameters reject. |
| Headers and credentials | Enabled ordinary headers retain order. Transport-owned and Connection-nominated headers are omitted with warnings; WebSocket upgrades reject. Literal Basic/Bearer map to native auth. Explicit Cookie disables the live Cookie Jar. Supported redirect and paired Cookie Jar send/store settings map to native controls; unsupported URL/body rendering and asymmetric Cookie Jar settings reject. Unsupported auth and template syntax reject. |
| Body | No body, JSON, textual MIME and URL-encoded form parameters are supported. Repeated form fields and empty values stay ordered. Binary, file and multipart data reject. |
| Base and child environment | Flat string/number/boolean values become editable variables; child values overlay the base in separate environments. Null/nested data and deeper inheritance reject. Sensitive keys and all variables in an `isPrivate` environment are marked private. |
| Cookie Jar and API Spec | Empty workspace resources are omitted with explicit warnings. Any cookies or nonempty API Spec content reject before saving. |
| Privacy and export | Default MoleAPI backup screens mapped credentials, URL-encoded form fields and copied credential values, and clears the opaque original source; full backup keeps exact V4 bytes. Postman/OpenAPI/HAR export rejects while exact source mappings are unverified. |

Local evidence so far: formats cases cover the representative V4 fixture, explicit/implicit workspace roots, optional export marker, disabled Basic/Bearer semantics, folder/request/environment mapping, duplicate/cyclic/dangling resources, query conflicts, unsupported auth/templates/body/resources, 5 MiB/1,000-request limits, default/full privacy and Connection header filtering. A hosted owner session imported and saved the source, sent exact GET query/Basic header and POST form/Bearer bytes to a checked local fixture, denied another owner and verified private/full exports. A standalone CLI process imported two requests, listed them and exported a screened native backup. A 390px hosted browser pasted the V4 JSON in English and Chinese, created and reloaded workspaces, sent the imported GET request to a checked local health endpoint and showed no document horizontal overflow. The focused import dialog axe scan reported zero violations and one incomplete contrast analysis due background inference.

The committed fixture follows Kong's documented V4 resource shape but was authored for this repository. Separately, a [public V4 export](https://github.com/andreviapiana/Find-a-Friend-API/blob/77bb95c6c151ac6d55432d9e6eec8c96ac13c6d4/export) with SHA256 `60f84dde9f02b2e912fe0267e2c55aab0d44c51c74ae102db3b9566f23cd9781` passed a fresh local CLI import after the review fixes. The external file is not vendored because its credentials were not audited for publication; temporary test copies were removed. An export observed directly from a running Insomnia application remains unverified. The browser exercised paste import, not the native file picker. After review fixes, the full formats/server/CLI Rust suite, strict Clippy, scoped rustfmt, diff check and embedded server/CLI builds passed; prior 370 frontend tests and production build apply to unchanged UI source. Independent re-review found no remaining merge blocker. Fixed-head three-database/Docker/native package checks and installed package smoke remain pending.
