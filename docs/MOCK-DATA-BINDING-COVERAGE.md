# Data-driven Mock binding coverage

Scope: the declarative part of `mock-012`, specified in [mock-data-binding.md](specs/mock-data-binding.md). Saved Mock examples may bind to a saved read-only dataset view and return all rows or the first row without authored JavaScript. Existing Mock scripts can still modify the resulting response. Literal CSV/JSON and query-backed Data datasets use the existing bounded worker and refresh bridge. An absent binding keeps old static and schema behavior.

Workspace validation requires script mode v2, a saved dataset and SQL-backed view, JSON-compatible response media, an HTTP request, and at most 16 explicit path/query/header parameters. It rejects credentials, cookies and private query/header names. Runtime values come from the existing screened incoming request, are capped at 512 bytes each, and reject missing or duplicate values. SQL remains the saved view; values are bound parameters. An empty `first` result returns JSON `null` with 404, including when the query-backed Data request itself returns zero rows; `rows` returns `[]`. A selected binding failure never returns the saved static body.

Public shares require explicit dynamic permission. The share digest covers bound dataset content and its referenced Data request, so source edits invalidate the old token; revocation and existing in-flight owner/revision fences still apply. Call logs contain metadata only. Default MoleAPI backup withholds the binding and private dataset source; full backup restores both. External exports reject unsupported bindings rather than silently dropping them.

Independent review found four Important gaps: a `cookie` query parameter was admitted, non-JSON response headers blocked UI conversion, an old linked-schema validation could update another workspace's draft, and a zero-row live Data source failed before the `first` response could become 404. Regression tests reproduced each and now pass after screening cookie keys, normalizing enabled Content-Type on binding selection, fencing the async callback by workspace ID, and allowing an empty query-backed snapshot only for the selected declarative Mock path. Ordinary runner datasets still require nonempty rows.

Local source evidence after those fixes: `cargo test -p moleapi-core --test validation` (11 passed), `cargo test -p moleapi-script-runtime --test runtime` (17 passed), `cargo test -p moleapi-formats --test mock_scripts` (7 passed), `cargo test -p moleapi-server --test mock --test mock_public --test database` (31 + 15 + 2 passed on locally configured SQLite), strict all-target Clippy for the four changed Rust packages, 436 frontend tests across 115 files, a production 46-chunk frontend build and the refreshed embedded server build. Tests cover old/new serialization, invalid references and private parameters, literal and query-backed views, request path/query/header binding, duplicate/missing values, empty first rows, script layering, no fallback on Data failure, selected-only access, dynamic share permission, owner denial, source edit and revocation, simulated fault/rate admission before data reads, cancellation during a delayed selected call, output limits, log privacy and backup behavior.

Actual hosted 390px browser: an English owner selected a saved view and first-row shape, added a path parameter, saved revision 2, then an owned routed GET returned the selected JSON row. A share without dynamic permission was rejected; an explicitly permitted anonymous routed GET returned the same row. Reopening the editor in Chinese retained the binding controls. Document width stayed 390px in both languages. After the review fixes, the rebuilt embedded server was reopened at 390px; the saved binding, path parameter and no-overflow layout were rechecked. The owner screen's axe WCAG A/AA audit found zero violations and two incomplete checks on existing editor/pseudo-element rendering.
