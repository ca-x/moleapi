# Git-triggered API test configuration

A shared modular Rust generator now produces GitHub Actions, GitLab CI and Jenkins declarative pipeline files for native CLI collection/scenario execution. CLI `ci --config FILE` reads explicit JSON and returns a preview/file envelope; `--output` exports only the generated configuration through the existing private atomic/no-overwrite writer. This command initializes no database/router and does not look up service credentials. The same generator serves owned `/api/workspaces/{id}/ci-preset` requests and the hosted/desktop settings panel.

Inputs bind remote saved workspaces or repository collection files, exact collection/scenario selection, environment, saved dataset or prepared CSV/JSON file, iteration count, collection request filters, notification mode, report format/language, CI secret reference and exact branch names. Caller literals are bounded; controls/GitHub expression delimiters are rejected. Remote service URLs reject credentials/query/fragments. Secret names are references rather than values. Native file presets remain silent because temporary imported workspaces do not contain separately stored notification targets. Existing CLI failure/empty/usage/interrupt semantics remain intact.

Workspace routes validate owner, saved revision, root/source match, selected collection/scenario/environment/dataset, distinct subtree-bound request filters and owned notification IDs. Dataset parsing and iteration bounds reuse the shared core parser. File presets use native workspace export IDs; a selected saved dataset must survive the default private projection, otherwise the user supplies a prepared repository data file. Generating a preset does not execute requests, mutate saved sources, install a runner or register a remote webhook/job.

## Provider behavior

- GitHub: push, pull_request and workflow_dispatch; optional exact target-branch selection for push/PR events (manual dispatch remains available); content-read permission; self-hosted Linux runner with an already installed CLI; remote-mode fork PRs are skipped because repository secrets are unavailable. Secret binding uses `secrets.NAME`. Always archive the report without replacing the failed step status.
- GitLab: push, merge-request and web rules; optional exact current/target branch selection; native shell script; optional configured secret alias without a self-reference for the default name; always archive the report and publish JUnit when selected. The job uses the `test` stage.
- Jenkins: Pipeline from SCM polls for commits every five minutes; optional exact multibranch current/target selection; remote mode binds the configured string credential. Stage-local always/post archives the report and publishes selected JUnit, avoiding publication from a skipped stage. Jenkins needs Credentials Binding and artifact/JUnit publishers.

Use POSIX runners with the CLI and usual shell utilities installed. The reserved `.moleapi-ci/report.<format>` is removed before execution so an assertion failure or pre-run failure cannot publish a prior build's report. Values use the CLI’s `--option=value` syntax so leading hyphens remain literal values. YAML serialization uses mature serde_yaml_ng; POSIX argument quoting uses shlex; GitLab literal branch matching uses regex escaping; Jenkins script/branch literals use Base64 plus Groovy's standard decoding/JSON APIs. The app does not implement these grammars or run an untrusted interpreter during generation.

## User flows and exact evidence

The settings section lets users select provider/source/execution/environment/data/filter/notification/report/branch options, using the existing notification picker and a subtree-bound request picker, preview/copy/download configuration and separately export its default-private native source snapshot. Save the workspace first. Account/credential/source/revision/content/lifetime fences reject late results and late native file-picker writes. Exported snapshots must match the saved ID/revision. UI copy is English/Chinese and uses existing Radix/CodeMirror/file-save modules.

Actual scoped local evidence:

- Two formats fixtures parse GitHub/GitLab YAML, check events, secret references, report publication and Jenkins SCM/credential behavior; use mature shlex to round-trip hostile-looking quoted command arguments and reject controls/workflow expressions/invalid URL/options/credential fields.
- One actual CLI/process fixture executes the generated POSIX script against a local HTTP/Postman collection with leading hyphens, quotes and `$()` in names/paths. Two passing executions yield0 and parsed JUnit. Replacing assertions yields1 and fresh failure JUnit. No extra shell command runs; configuration preview/export does not initialize a database, and existing output is protected.
- One hosted API fixture exercises ownership/unauthenticated/source/revision/selection/notification validation, preview generation and unchanged saved workspace/empty history.
- Three frontend fixtures exercise saved revision/request shape, lack of bearer values in payloads, preview/download and picker fences, same-account credential changes discarding late results, dirty-source disabling and default-private snapshot/revision checks. TypeScript and translation catalogs pass.

Existing execution/protocol/report fixtures were not repeated without relevant changes. Native external CI job execution, Jenkins plugin/sandbox/SCM behavior, GitHub/GitLab service linting/branch edge cases, all runner platforms, binary installation and Docker distribution remain for the later unified integration checks. This is usable configuration generation with real native-script evidence, not proof of every CI-platform configuration or completion of the395-capability matrix. No local Docker build or formal review was run. The parent main merge/new release objective remains active.
