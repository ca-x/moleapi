# Parallel scenario coverage

Saved scenarios now carry named parallel blocks with2–8 consecutive enabled member IDs and1–4 concurrency. Validation enforces unique IDs, bounded labels, ordered contiguous members, no overlaps and no declarative entry into an interior member. Default empty fields keep old scenarios readable. The bilingual Radix editor selects a starting member/count, name and concurrency, shows membership, edits concurrency and explicitly removes blocks. Remove a block before deleting/disabling/reordering its member steps; members retain their canonical request references, conditions and repeats.

## Execution and merge

The coordinator uses mature futures-util buffered futures and Tokio, sharing existing finite request execution rather than implementing another transport/script engine. Each member receives a fork of the same initial project/environment/data/temporary state and its effective collection chain/overlays. Members retain their own variables and prior response across repetitions and never read peer writes. Repeats execute in bounded rounds; a false condition ends that member's repeats. Reports use saved member order within each round regardless of response completion order. After joining there is no unique previous response; subsequent steps should consume extracted variables rather than assume one peer's response.

Every launched visit consumes the existing1000-step run budget, including condition skips. The existing deadline, cancellation/job, owner/workspace admission, script slots and run capacity apply. Recheck admission before a yielded condition sends a request and before final merge. Cancellation drops unfinished work; completed batch histories can precede a later cancellation, without pretending network rollback. At most eight bounded request/response outcomes are held per round; report responses are trimmed through the existing8MiB accounting rather than retaining every repeat body.

Request history is deferred until a round's private taints are unioned. The exact resolved/mutated request and effective environment remain available to the ordinary history writer; this protects a peer body containing another member's extracted token. Failed work with uncertain provenance conservatively withholds peer history text. Skipped requests create no history. Serial execution uses the same deferred implementation through a wrapper retaining its previous immediate-history behavior.

At join, compare final write intents by scope/collection namespace/key. Equal values agree; differing values or deletion versus assignment stop with parallel_variable_conflict, count a failed join and apply no shared updates from this block. Approved noncollection maps and collection overlays apply atomically after combined size/entry validation. Different collections may update identically named variables independently. Private taints are retained even when the merge is refused. Canonical workspace data is unchanged.

Peer results mark variable_updates_applied=false. The browser/native hook ignores peer setters and applies approved final parallel_variable_updates once; those values reflect any later sequential overwrite or deletion. This avoids completion-order or report-order last-write-wins. Prior successful blocks' final updates remain available if a later block stops.

Default native backups screen copied private names, remove privacy-disabled members and drop blocks with fewer than two safe members, retaining importable references. Explicit backups preserve exact blocks/controls. Existing workspace CAS/version/sync services persist definitions; remote servers discarding blocks cannot acknowledge synchronization.
