# Workspace documentation search coverage

Scope: owner-only search of the current workspace draft under `documentation-009`, specified in `docs/specs/workspace-document-search.md`. This is not a public documentation-site index.

The Documents page searches authored Markdown titles/private sources and saved request names, methods, credential-screened URL structure, descriptions, eligible text bodies, response example names/bodies and enabled query/header names. It excludes auth credentials, query/header values, disabled rows, and URL userinfo/query values/fragments, including for templated and scheme-relative URLs. Literal Unicode case-insensitive AND terms rank title matches first, preserve source order within a rank and return bounded plain-text excerpts. Queries over 128 characters return no results; the page renders at most 100 results with the true total and a refinement hint. The search is derived from the current unsaved draft in memory, never persisted or sent to an endpoint, and clears on account/workspace change. A document result selects its exact document and focuses its heading; a request result uses the existing current account/workspace/request guard before opening the request editor.

Local evidence: pure search regressions cover Unicode/literal metacharacters, multi-field terms, title ranking/order, private source, disabled/credential omission, URL userinfo/query/fragment screening for literal/templated/scheme-relative authorities, Turkish lowercase expansion and Greek contextual casing, exact draft retention, 160-character excerpts, overlong queries and a 101-match budget. Two page regressions cover private-source navigation, request navigation, stale account refusal and account/workspace search reset. An independent reviewer found and rechecked the URL privacy and Unicode excerpt fixes, with no remaining high-confidence issue. The final full frontend suite passed 406 tests; TypeScript, production frontend build, the 46-chunk static ESM cycle verifier and embedded server/CLI builds passed after the fixes.

At 390 px, the embedded English hosted UI searched a saved private Markdown source, opened its document and focused the title, then searched a saved request and opened its existing editor. No search or result-click API request was captured. After switching to Chinese, both a matching result and the zero-result state displayed without page-wide overflow. Focused axe reported zero violations and one incomplete contrast analysis because theme pseudo-elements obscured the inferred background.

A final embedded browser used an unsaved URL with userinfo password, `token` query value and fragment; the server correctly rejected saving that URL. Search still followed the local draft: password and token-value queries returned zero results, while searching the host showed only `https://example.test/animals?token&visible` in its excerpt. The page stayed 390 px wide, and no search request was sent.

Open: fixed-head CI/database/Docker/native package gates and installed smoke. Published-site indexing/search, cross-workspace permissions and access rules, and the broader documentation/navigation matrix remain required; this local view does not close full `documentation-009` or the 395-item goal.
