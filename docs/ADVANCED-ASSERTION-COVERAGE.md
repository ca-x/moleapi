# Structured response assertions

Finite HTTP execution and collection runs share response header equality, regex match/capture, JSONPath, XPath1.0 and JSON Schema checks alongside existing status/duration/contains/JSON Pointer assertions. The core trusted evaluator uses mature fancy-regex0.19.2, jsonpath-rust1.0.11, sxd-document0.3.2/sxd-xpath0.4.2 and jsonschema0.58.5. No application query/schema/XML parser or regex engine is implemented.

JSONPath returns a scalar for one match or an array for multiple matches; missing matches fail. Expected values use JSON encoding. XPath compares text/nodes to literal expected text and numbers/booleans to parsed scalar values; root namespace prefixes are bound and local-name() supports default namespaces. Empty node sets fail. Regex target is a pattern; empty expected accepts a match, otherwise compare first capture or whole match. Advanced lookaround/backreferences are supported under a100k backtracking bound. Header names are case-insensitive, with any repeated header value satisfying equality.

Schema expected is an inline JSON Schema, with optional JSON Pointer target selecting the response instance. Format checks are enabled. The mature advanced regex implementation remains available with backtracking/compiled-size limits. External schema resources are disabled with an explicit retriever; no file or URL is loaded. XML DTDs are rejected before XPath parsing. Structured queries on binary/non-UTF8 or truncated bodies fail rather than validating replacement/incomplete data.

Untrusted hosted/native checks run in an application worker before post-response scripts. It has512 MiB heap cap,2s absolute deadline,16 MiB input and4 MiB output bounds, failure kill/reap and kill-on-drop. The application dispatcher starts before database/CLI/window initialization. Header/status/duration-only evaluation omits unnecessary body transfer; binary byte copies are never passed. Worker failure becomes explicit failed results, never passes. Core direct evaluation is for trusted library/tooling use.

Request definitions allow100 checks,4 KiB target expressions and64 KiB advanced expected/schema text. Structured documents have50k-node/64-depth bounds. Oversized actual/expected diagnostic fields are omitted wholly, avoiding partial private fragments; original definitions remain unchanged. History privacy stays in the common pipeline. The editor exposes the new kinds and a mature JSON Schema editor with theme support.

Evidence: JSONPath multiple/scalar matches, root-prefixed XML/numeric/boolean XPath, regex captures/lookbehind, schema nested types/patterns/email formats, missing queries, denied external schema refs and XML entities; real response/collection checks through the actual worker; forced2s process timeout producing failed checks; whole-field diagnostic omission; legacy runner behavior; editor/catalog/type/production frontend and scoped strict Clippy. Other dialects, non-finite protocol event assertions, namespace overrides and automatic schema selection from API definitions remain required broader capabilities. No complete-product or release claim is made.
