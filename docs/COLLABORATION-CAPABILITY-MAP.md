# Workspace collaboration capability map

Authority: `collaboration-002` through `collaboration-004` in `FEATURE-MATRIX.md`. This map separates account membership, authorization and client behavior so sharing a workspace never relies on a copied workspace document.

| Module ID | Responsibility | Depends on |
| --- | --- | --- |
| `workspace-membership` | Hosted invitation creation/acceptance/revocation, indexed account-to-workspace membership, owner/admin/editor/viewer roles | Hosted accounts, canonical workspace storage |
| `workspace-access` | Resolve actor and canonical owner, apply deny-by-default route permissions, fence in-flight work after role/revision changes | `workspace-membership` |
| `member-workbench` | Shared workspace list, role-aware bilingual controls, safe viewer projection and current-account fences in web/native clients | `workspace-access` |
| `collaboration-audit` | Record actor, owner, resource, action and result for member/role changes and shared writes without secret payloads | `workspace-access` |

Build order: `workspace-membership` → `workspace-access` → `member-workbench` → `collaboration-audit`. The first release gate covers all four together: an accepted invitation must lead to useful, correctly limited workspace access. Organization/group policy, SSO/SCIM, comments, presence and broad resource-level custom roles stay in their own matrix rows.

Shared collection runs support creator-bound, actor-audited Stop with an internal membership-epoch job key and bounded early cancellation. The result retains the client job ID and saved cancelled report. One workspace-level active-job region retains creator Stop across tabs, edits, Save and collection removal; only matching inline output is shown, and exact job identity fences late callbacks. This uses the executing instance's registry; distributed job routing remains separate work.

Current audit checkpoint: invitation, membership and shared workspace writes append actor-labelled success events transactionally; owner/admin hosted sessions can read the latest 100. Shared collection runs, canonical saved-request execution, finite HTTP/GraphQL query/mutation draft execution, saved SSE/WebSocket/Data/TCP/Socket.IO/gRPC/GraphQL subscription sessions, saved Mock preview and routed Mock matching record the actor at admission and poll membership across instances while running. Draft HTTP/GraphQL, routed Mock matching and member live sessions also fence workspace revision; live sessions fence creator credentials. Linked Mock Schema selection and literal dataset preview and OpenAPI specification candidates and canonical GraphQL introspection/linked schema and saved-request Proto import/gRPC schema/Reflection have explicit actor-audited member routes with membership and workspace revision fences. Editors/admins can read saved history, reports and Mock calls with a final membership check. Other protocol sessions, public Mock share management and resource actions remain closed to members, so their future audit entries and cancellation fences are still part of this release gate.
