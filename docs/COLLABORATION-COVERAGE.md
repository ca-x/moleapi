# Hosted workspace collaboration coverage

Status: integrated feature still in progress in `feat/workspace-collaboration`. This file records evidence for the current worktree, not a released or merged capability. Authority: `docs/specs/workspace-collaboration.md` and `docs/COLLABORATION-ROUTE-POLICY.md`.

## Implemented paths

| Capability | Current evidence | Boundary |
| --- | --- | --- |
| Invitations and members | Hosted session create/list/revoke/accept, owner/admin role changes and removal, single-use digest tokens, same-account retry, per-acceptance generation and indexed cursor-paginated membership; cross-instance acceptance/rejoining and deletion/recreation tests | No organization/group ACL or delivery integration |
| Shared workspace data | Explicit owner/workspace GET for viewer-safe projection and editor/admin CAS PUT; owner IDs remain distinct when workspaces share an ID | Full editing parity with every workbench resource is pending |
| Shared execution | Editor/admin collection run, canonical saved-request execution and saved Mock example preview use the owner workspace, audit the real actor, check membership concurrently every 200 ms and withhold results after removal/rejoining or role change | Ad hoc request, public Mock share, protocol and runner routes remain owner-only; outbound side effects already sent before revocation cannot be rolled back |
| Saved results | Editor/admin history, report summary/detail/step response and Mock call reads recheck membership before returning | Viewer private-result access and member report mutations/export remain closed |
| Audit | Successful invitation, membership and shared workspace writes append within their transaction; collection run start records the actor; owner/admin session lists latest 100 | Other resource actions need actor attribution before member access opens |
| Hosted client | Owner/admin invitation/member controls, one-time URL fragment link, current-session acceptance, distinct owned/shared picker keys with owner and role, viewer read-only view, basic editor CAS request/Mock example edit and save, collection run, saved-request send/Mock example preview/history/report/Mock call view, pending-save edit retention, unsaved-change guard and shared query cleanup on workspace/account exit | Advanced request/Mock editor parity, remaining account switch/cache stress tests, native hosted sync and package validation remain open |

## Current verification

- Local SQLite: `cargo test -p moleapi-server --test collaboration --test database --no-default-features` passed 8 collaboration and 2 database tests, including member CAS editing of a saved Mock example, saved Mock preview/call permissions, an intentional saved-example 401 marker, role downgrade during a preview, same-role rejoining during an in-flight run and cursor pagination. The valid large viewer projection and migration upgrade unit tests passed on an earlier tree. Re-run on a fixed branch head before publication.
- Strict server Clippy, Rust formatting and diff checks passed for the current source. The full frontend run passed 462 cases; the production build verified 46 chunks and the embedded server build passed. The shared editor tests cover Mock create/edit/delete, invalid status, same-ID request selection, conflict recovery, preview selection, stale/late response isolation after edits and saves, pending-save edit retention and delayed request result isolation. Independent editor-slice review found two Important state bugs; both were fixed and re-reviewed. Fixed-head CI for the editor extension remains pending.
- Real Chromium at 390 px, English: owner created a viewer invitation, another account accepted, opened the shared picker, saw read-only content, became editor, saved a CAS update, resolved a concurrent owner edit, then lost the open view after owner removal.
- Real Chromium at 390 px, Chinese: after a fragment-navigation fix, an already open member session accepted a second invitation and opened the shared editor. An unsaved editor draft triggered a leave guard; confirming discarded the draft and cleared the view. Captures: [English viewer](images/workspace-collaboration-viewer-en-390.png) and [Chinese editor](images/workspace-collaboration-editor-zh-CN-390.png).
- Real Chromium at 390 px, English: a member opened a canonical saved request through the paginated picker and received a local HTTP 200 response in the shared editor. Capture: [saved request execution](images/workspace-collaboration-saved-request-en-390.png).
- Real Chromium at 390 px, Chinese and English: an editor opened a saved Mock example, received its actual HTTP 201 response and saw the new call in shared history. Both views fit the viewport without horizontal overflow; browser console had no errors. The inactive tab contrast issue found by axe was fixed by using outlined tabs; the final Mock view has zero automated WCAG A/AA violations and one textarea contrast check requiring manual review. No horizontal overflow or browser errors were observed. Capture: [intentional Mock 401](images/workspace-collaboration-mock-auth-401-zh-CN-390.png).
