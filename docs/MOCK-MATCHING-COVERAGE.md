# Owner-scoped Mock matching coverage

Scope: `mock-004` and `mock-005`, `docs/specs/mock-request-matching.md`, branch `feat/mock-matching` stacked on the v2 Mock script branch. The explicit saved-example GET route remains available.

The new owner-authenticated `/api/mocks/{workspace_id}/{path}` route selects saved HTTP examples by method and path. A `{name}` path segment matches one nonempty segment. Enabled saved request URL/query pairs and optional per-example query/header/exact UTF-8 body conditions must all match. Repeated pair values are counted rather than treated as a set; header names ignore case. A matching rule outranks a default example; higher priority, more literal path segments, more conditions and then authored order break ties. The selected example uses the existing static response filter or bounded v2 Mock script. Incoming owner credentials, cookies, sensitive query keys and hop-by-hop/connection-nominated headers are excluded from matching and script input. Request body admission is capped at 1 MiB.

Local evidence at the feature commit: core validation rejects unsafe or oversized rules and retains old-example JSON compatibility; default MoleAPI backup withholds private criteria and full backup restores them. Real local/hosted route tests cover selected/fallback body and status, path variables, repeated query values, priority, method, owner isolation, nominated-header exclusion, oversized body and selected-only script execution. A 390px hosted browser imported a request/example, authored a query match, saved and reloaded it, then observed 202 `matched` for `mode=fast` and 404 for `mode=slow`; English and Chinese controls rendered without horizontal overflow. A reload-only UI failure from omitted empty JSON arrays was reproduced and fixed. Local suites: 145 core, 88 formats, 311 server passed with 8 existing ignores and one local Java catalog test excluded because the pinned OpenAPI Generator JAR was not prepared. Focused Mock tests: 10 passed; full frontend: 357 passed; production web and embedded server builds and scoped strict all-target Clippy passed. Independent review, configured three-database CI and current-head native package gates remain open.

Open Mock work: schema-driven fake data, call logs, public permissions, simulated delays/failures and complete native package acceptance. This slice does not close the entire Mock module.
