# Bounded composed Mock Schema coverage

Scope: the extension specified in [mock-schema-composition.md](specs/mock-schema-composition.md), building on the explicit and saved OpenAPI linked response modes. This is partial coverage of `mock-002`; field-name generation (`mock-003`) remains open.

The shared generator now accepts 1–16 `oneOf` or `anyOf` branches, 1–16 object-producing `allOf` branches, a two-type union containing exactly `null` and one supported type, and 1–32 `prefixItems` with `items` as a Schema, `true`, or `false`. It tries union branches in source order and validates each result against the full composed Schema. `allOf` merges generated objects and rejects conflicting shared values; tuple output respects min/max lengths and forbidden additional positions. Saved OpenAPI response normalization preserves supported composition and nested local component references; the nullable-type and tuple forms are OpenAPI 3.1 forms. Direct, routed and public Mock calls use the existing bounded worker, permissions, source digest and response path.

The existing 256 KiB input, depth 64, 10,000 node, 256 candidate, 1 MiB output and eight runtime worker limits remain. External references and runtime retrieval remain disabled. Unmodeled composition siblings, arbitrary multi-type unions, boolean root Schemas, general `allOf` solving and non-object intersections reject at save time. Static examples without a selected Schema retain their old body. Default backups still omit potentially private authored Schemas; full backups retain them.

Local evidence: core cases cover valid and ambiguous unions, failed referenced branch fallback, distinct and conflicting `allOf` fields, nullable tuples, tuple limits and global depth/node/candidate budgets. Saved OpenAPI core cases cover nested component refs and tuple normalization. Real server tests cover authored direct/routed tuple generation, linked direct/routed `allOf` generation, public composed output, and public linked-source change invalidation and rotation. The core/formats/server Rust suites, three new server cases, strict core/server test Clippy, 375 frontend tests, production frontend build and embedded server build passed on this branch. The initial full Rust run failed because this isolated worktree lacked the pinned OpenAPI Generator JAR; its SHA256-matching copy was staged from an existing worktree, the specific generation test passed, and the full relevant Rust suites then passed. Independent read-only review found a nullable tuple save rejection; commit `62bab42` fixes it and adds regression and budget cases, and re-review found no remaining Critical or Important issue in that fix.

An owned hosted browser at 390px saved an authored `allOf` Schema, previewed `{"id":3,"name":"Ada"}`, reloaded the workspace and previewed the same result. Authenticated direct and routed browser requests both returned HTTP 200 with that exact JSON and `application/json`. English and Chinese editor views retained the authored Schema, and both had document width equal to the 390px viewport. The Chinese dialog's focused axe check reported zero violations and zero incomplete checks after the explanatory copy was updated to list composition and tuples; the English dialog also had no document overflow. This browser fixture enabled private-network calls only on its isolated local server so the saved request could use its own health endpoint.
