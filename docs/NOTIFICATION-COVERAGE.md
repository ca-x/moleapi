# Scheduled notification channels and delivery

Reference options were checked with agent-browser against Apifox notification-targets/events and Postman integration/PagerDuty documentation. The target catalog exposes Webhook, Slack, Teams Workflow, WeCom, DingTalk, Feishu, Jenkins, PagerDuty and SMTP Email. Provider-specific JSON envelopes, robot signing and receipt handling are distinct; listing a channel does not establish vendor cloud/app-installation parity.

## Configuration and events

Owned workspace targets have name/type/enabled/outcome filters/change-only and English/Chinese message locale. Private endpoint URLs, signing/routing keys and SMTP credentials use separate owner/workspace credential documents. Metadata returns origin, SMTP public settings and presence flags, never private URL paths/query tokens/passwords. Omitted update fields retain their values; explicit empty values clear them. SMTP recipient/public-setting edits preserve omitted username/password fields. This matches the existing private vault storage model; documents are not falsely described as encrypted at rest.

Scheduled definitions select up to20 unique owned target IDs. Matching completion/interruption outcomes enqueue deliveries transactionally with their occurrence state. Notifications carry only status/counters/time/report ID and screened workspace/task names; live response bodies/logs/variables are excluded. Change-only filters suppress consecutive equal outcomes. Invalid/removed targets and the bounded pending queue contribute explicit skipped counts instead of changing the completed run outcome. Ordinary interactive/scenario/CI completion is now connected; see [run event bindings](RUN-NOTIFICATION-EVENT-COVERAGE.md). Manual queued cancellation and workspace collaboration events remain unconnected.

## Transport and queue

HTTP uses the shared DNS-checked/pinned core client, no redirect or implicit environment proxy, verified TLS and a20s transport deadline. Receipts are capped at64KiB. Generic Webhook uses mature HMAC-SHA1 and X-Hub-Signature; DingTalk/Feishu use mature HMAC-SHA256/Base64 with their different timestamp/key/message forms. Jenkins uses Bearer credentials. Slack text, Teams Workflow Adaptive Cards, WeCom/DingTalk text, Feishu text and PagerDuty v2 trigger/resolve envelopes are separate. PagerDuty uses a stable schedule dedup key. Robot/Slack/PagerDuty HTTP200 receipts with application errors do not count as success.

SMTP reuses Lettre0.11.23 for mailbox parsing, MIME and the protocol, with STARTTLS/TLS or explicitly selected trusted clear SMTP. Validate destination addresses with the existing private-network policy and connect to a checked IP while retaining the original hostname for TLS. Clearly refused/unreachable addresses permit another checked address; ambiguous post-send errors do not switch addresses inside the same attempt. Stable delivery IDs also supply stable Message-ID headers. No custom production SMTP parser/process is introduced.

The router owns a weak delivery-engine lifetime. Two worker slots claim60s DB leases before sending; a shared database cannot claim the same active delivery concurrently. Up to1000 pending workspace deliveries and200 completed records are retained. Transient HTTP408/429/5xx, connection/deadline and transient SMTP failures retry at bounded exponential delays, at most three attempts. Permanent receipts fail immediately. Inspect sanitized status/attempts/HTTP code/fixed errors; explicit terminal retry uses the current enabled target version. Target changes/deletion/disable cancel obsolete pending versions. Stable idempotency headers help receivers deduplicate, but timeout/crash replay can duplicate already accepted external messages; no exactly-once or final human-recipient acknowledgment claim.

## Interface and evidence

The bilingual React/Radix target manager offers all channel types, masked credentials, SMTP/recipient/TLS controls, outcome/change filters, enable state, credential retention, ledger inspection and explicit retry. The schedule editor selects configured targets. Browser/native account/workspace/editor fences prevent late save state from changing another context. Definition/task/delivery storage is operational per serving instance and is not yet part of workspace synchronization/export.

Six actual local fixtures prove signed Webhook delivery,503 retry with stable delivery ID and no copied private endpoint values, robot rejection despite HTTP200, explicit retry, owner isolation/private-network blocking/cascade, real SMTP MAIL/RCPT/DATA and MIME headers, target revision cancellation, repeated-outcome suppression, and SMTP omitted-password retention/explicit clearing. Provider payload/receipt unit tests cover all eight HTTP schemas and PagerDuty recovery. UI cases prove private channel creation, complete option listing and withholding-aware updates; existing schedule/report UI and catalogs passed. TypeScript, production frontend and scoped Clippy passed. The schedule competing-engine regression remains passing after event integration. No test sent a message to a real third-party recipient.

Vendor cloud endpoint/TLS/auth delivery, bot/OAuth installation, additional Datadog/New Relic/Splunk/Statuspage integrations, collaboration event bindings and executable CI/runner integration, credentials-at-rest encryption, distributed runner enrollment, broader feature matrix and final unified platform/database/browser review remain unfinished before main merge/cleanup and the new GitHub Actions release. No local Docker or package/release build was performed.
