# Native public Mock listener coverage

Scope: desktop offline portion of `mock-011`, `docs/specs/mock-native-listener.md`, stacked branch `feat/mock-native-listener`. Hosted public Mock capability checks, response limits, logging and token privacy remain the same shared implementation as PR #18.

The desktop IPC router remains offline until the owner explicitly starts a separate listener. Start accepts `127.0.0.1` by default or `0.0.0.0` only with `allow_lan=true`, plus an explicit/automatic port. Its TCP router mounts only the public direct/routed Mock paths; management, authentication, workspace data and embedded assets are absent. Status returns the actual bind and same-device origin; stop cancels in-flight calls and closes the port. A weak listener reference in `AppState` and a strong outer-router extension avoid a lifecycle ownership cycle; dropping the IPC router aborts the listener.

Local source evidence: three real socket integration tests cover inactive default, invalid/LAN bind denial, explicit LAN acceptance, occupied port, start/status/repeat-start, anonymous public response, rejection of management and private routes on the public socket, owner IPC revocation, stop/restart, router-drop cleanup, hosted-control denial and cancellation/released delay permit on stop. The native UI now offers explicit listener controls, actual origin, LAN/HTTPS warning and disables creation/rotation while stopped; revocation stays available. The full frontend suite passed 366 cases, production frontend build and the full server test suite passed locally. After stop/start serialization and cancellation priority fixes, the three native socket and focused UI tests passed again, followed by full frontend 366, strict all-target server Clippy and embedded server build. Actual graphical native UI, configured databases, Docker and installed-platform packages remain to verify.

The listener itself is plain HTTP. When bound to all interfaces, external callers need a trusted HTTPS reverse proxy and must replace the returned loopback host with the device address. Token URLs can become invalid after a port-0 restart; rotation issues a new one-time URL. Custom domains, automatic discovery, TLS termination and organization permissions remain open product scope.

Independent review follow-up: reopening the dialog now displays the active bind and LAN/HTTPS warning from listener status, while initial status loading prevents a start/status race. A canceled public request receives the same no-store, no-referrer and CORS headers as other public responses. The native UI regression set covers both status cases; the socket cancellation test checks headers when the canceled connection remains available. Routed and dynamic cancellation still need dedicated wire evidence.
