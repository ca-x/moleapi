# MoleAPI v0.2.2

## 简体中文

修复自托管容器因空启动环境变量而无法启动的问题。

- 所有服务端启动选项均可省略，缺少参数值或环境变量为空时使用默认行为：监听 `127.0.0.1:8787`、SQLite 数据库 `./data/moleapi.db`、初始化令牌自动随机生成。
- 默认允许私有网络请求，适合调试局域网 API；可用 `--allow-private-network=false` 或 `MOLEAPI_ALLOW_PRIVATE_NETWORK=false` 禁用。
- `--allow-private-network` 和 `--allow-registration` 支持裸参数、`=true/false` 以及空格分隔的布尔值。公开注册仍默认关闭。
- 新增 `MOLEAPI_DATABASE` 用于设置 SQLite 数据库路径。

Docker 镜像：`ghcr.io/ca-x/moleapi:0.2.2`。容器默认监听 `0.0.0.0:8787`，继续将 `/data` 挂载到持久化卷。服务端归档需连同 `runtime/` 完整解压，并使用 `SHA256SUMS` 校验。

## English

Fix self-hosted containers failing to start when startup environment variables are empty.

- All server startup options are optional. Omitted values and empty environment variables use defaults: bind to `127.0.0.1:8787`, store SQLite data in `./data/moleapi.db`, and generate a random first-user setup token.
- Private-network requests are now allowed by default. Disable them with `--allow-private-network=false` or `MOLEAPI_ALLOW_PRIVATE_NETWORK=false`.
- Both boolean options accept bare flags, `=true/false`, and space-separated values. Public registration remains disabled by default.
- Add `MOLEAPI_DATABASE` for the SQLite database path.

Docker image: `ghcr.io/ca-x/moleapi:0.2.2`. Containers continue to bind to `0.0.0.0:8787`; persist `/data` with a volume. Extract server archives together with `runtime/` and verify downloads against `SHA256SUMS`.
