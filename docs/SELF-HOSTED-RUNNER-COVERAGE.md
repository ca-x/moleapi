## Workspace-scoped credential slice

Hosted credential management uses a login session to issue one bearer for one runner and workspace, list metadata and revoke by public ID. Only the digest is indexed in storage; the bearer appears once in the create response. The global guard restricts bearer access to claim/heartbeat/complete, and each state-changing agent transaction rechecks expiry and revocation under the account lock. Leases record the issuing credential ID; a replacement credential cannot complete an old lease. Revocation cancels only its active lease and leaves unrelated credentials and queued tasks intact. Workspace deletion removes scoped credentials, including before same-ID recreation.

The focused SQLite two-router fixtures cover owner/runner/workspace isolation, malformed and expired bearer denial, quota and deletion cascade, active lease cancellation, concurrent claim/revoke ordering and scheduled lease reconciliation. Existing runner and scheduled-runner fixtures use scoped bearers. Real CLI process fixtures use a private agent token file or environment variable for execution and SIGINT; the create command writes only to a private output file and prints metadata. Hosted UI tests cover one-time display, close/reopen clearing, explicit revoke confirmation and late account-change responses; native mode makes no hosted runner calls. PostgreSQL/MySQL, platform service installation and release evidence remain later gates.

The embedded hosted application was also exercised in Chromium at a 390 px viewport: first-account setup, workspace and runner registration, one-time 79-character credential issue, close/reopen without the secret, and confirmed revoke. The credential manager had zero WCAG 2 A/AA axe violations (14 passing checks). This checks the rendered management journey, not agent installation or other native platforms.
