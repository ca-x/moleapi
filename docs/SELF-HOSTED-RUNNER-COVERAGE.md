# Self-hosted runner execution coverage

The modular server runners registry/selection/tasks/agent/storage modules use existing account authentication, SeaORM documents/account locks, workspace lineage, crypto token hashing and Rust execution/report/notification modules. Shared core types expose metadata and claim contracts. No new protocol parser, database engine or script interpreter is introduced. Native CLI runs each dispatch using an isolated offline local router and existing private variable inputs. Metadata returns no snapshot/digest/token/report body. Claims explicitly deliver selected workspace credentials to a trusted owned runner.

Source IDs/revision, collection/scenario/filter/environment/data/iterations and notification ownership are validated before queueing. Account row serialization makes concurrent claims exclusive across instances and bounds quotas. One registered ID has one active task. Random90second leases persist only hashed tokens;20second agent heartbeat renews them. Cancellation/disable/revocation and source changes fence execution. Default attempt count1 prevents automatic replay; explicit2–3 permits lease-expired retries with possible repeated side effects. Task completion and shared redacted report/notification persistence commit atomically; repeated acknowledgement returns its existing report. Local history IDs are removed. Terminal snapshots are dropped and retention is bounded.

## Actual evidence

- Actual hosted/shared-SQLite dual-router fixtures: concurrent exclusive claims, owner isolation, metadata privacy versus explicitly credential-bearing dispatch, valid/wrong heartbeat, atomic report completion with repeated acknowledgement yielding exactly one report, canonical secret screening and absent worker-local history references.
- Actual hosted lease/state fixture: forced persisted lease expiry, explicit second attempt with a new token, stale first-token rejection, durable cancellation and heartbeat denial, default single-attempt exhaustion, owner revocation cancelling queued tasks, disabled runner cancelling an active lease.
- Actual hosted invalid-source/report fixture: missing collection/environment/data, duplicate/outside filters, iteration overflow queue nothing; changed workspace revision cancels an unclaimed task; malformed objects/tests or foreign request IDs create no partial report; explicit failed completion persists.
- Retention fixture:100 persisted older terminal rows plus current cancellation retains exactly100 summaries and the new task.
- Actual CLI process/HTTP fixture: register/queue, local Rust script/request execution with runtime secret header, owned redacted hosted report, unchanged canonical workspace, metadata report ID and empty one-shot agent.
- Actual Unix CLI process/HTTP fixture: SIGINT interrupts a live slow local request, returns130 and persists acknowledged hosted cancellation.

Both actual CLI/process fixtures and all four hosted state/retention fixtures passed locally. These scoped checks do not prove schedule targeting, browser/native UI, response history upload, service installation, all existing protocols/scripts through an agent, DB/platform deployments or full feature parity. Those remain in scope before unified formal review/main merge/release. No local Docker build or external job installation was performed. [Usage](SELF-HOSTED-RUNNERS.md) documents trusted credentials, polling/cancellation delays and replay risk.
