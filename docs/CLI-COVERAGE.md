# Native CLI coverage

The modular Rust `moleapi-cli` binary uses Clap4 and shared server/core/formats/generation modules. Local mode accepts an explicit SQLite path or an isolated temporary database. Remote mode uses an explicit HTTP(S) base URL and bearer environment/token-file input. Login writes a private token file. Offline initialization disables both stored schedule dispatch and notification delivery; serving applications retain their background behavior.

Commands provide resource metadata listing, persistent import/export, collection/scenario execution, selected environments and saved/temporary CSV/JSON datasets, iteration limits, explicit request selection by ID/unique name, CI origin/notification overrides, stored report export and the complete request-snippet catalog. Request filters are validated against the collection subtree, reject unknown/duplicate IDs and preserve collection traversal order. Filters cannot be combined with scenarios, whose ordered steps/branches remain intact. Clap supplies help, exclusive flags, enum parsing and discoverable command metadata with inherited global options/defaults/possible values.

Reports reuse owned redacted JSON/CSV/JUnit/bilingual HTML exports. Exit codes are0 passing nonempty execution,1 failing/empty/stopped execution,2 usage/transport/storage/export error and130 after Ctrl-C. Cancellation polls run and cancel together so a single SQLite connection is not deadlocked. Imported run workspaces are deleted after report export; stdout marks them temporary and does not advertise a persistent report ID. Cleanup failures are reported explicitly. Persistent import/run retains reports. Input and remote response sizes are bounded; redirects and base URL credentials/query/fragments are rejected. Diagnostics avoid returning raw credential-bearing API errors. Atomic private output refuses overwrite unless explicitly requested.

## Necessary process evidence

- `cargo test -p moleapi-cli --test snippets --locked`: actual offline process lists23 language families/55 adapters, imports a cURL request, lists/exports resources, generates a saved Python Requests snippet and rejects overwriting its source file.
- `cargo test -p moleapi-cli --test runner --locked`: real local HTTP fixture and CLI worker verify scenario/environment/data selection, response extraction before script assertions and following-request access,4 passing executions, parsed JUnit without extracted private values, failed/empty exit codes, selected-request runs, authenticated remote login/import/run/JSON report export,0600 Unix token permissions and absent-resource/unauthenticated rejection. A Unix SIGINT cancels live execution with130. During that live run, an enabled stored one-second schedule does not start; its persisted last-run stays absent.
- `cargo test -p moleapi-cli --test discovery --locked`: process-level command metadata/inherited options and invalid exclusive modes/credential-bearing URLs.
- `cargo test -p moleapi-server --test runner_selection --no-default-features --locked`: invalid filters/scenario combinations make no HTTP calls; selected descendant requests execute in original collection order.

All of these scoped checks passed locally. Snippet generation was checked before later CLI runner changes; reruns were limited to affected commands. This does not establish all protocol execution, every runtime/database/platform, full Newman compatibility, custom reporter support, performance/distributed execution or completion of the395-capability matrix. No local Docker build or formal review was run. CLI installer/release packaging and GitHub Actions updates remain deferred until functionality is complete. [CLI examples](CLI.md) cover GitHub Actions, GitLab and Jenkins invocation; they require an installed CLI and are not evidence of complete CI/platform integration.

## Embedded coding-agent entrypoint

`skill` now prints a compiled-in standard MoleAPI SKILL.md, exports it through the existing private atomic writer, or returns its fixed Markdown/Codex-interface file bundle as JSON. It runs before database/router/credential initialization; `schema` remains independent as well. The guide covers actual native/remote resources, selected environments/data/scenarios/filtering, original report/exit-code semantics, request-code catalog discovery, token management and the optional original Newman runtime. `list requests` provides exact IDs/names/methods/containing collections without request URL/body/auth fields, so an agent can select a saved request without a full workspace export. Clap owns paired snippet fields, required run source selection, option conflicts and value cardinality; schema reuses its introspection.

Actual `cargo test -p moleapi-cli --test skill --test discovery --locked` passed three process fixtures: source/embedded/export byte identity, fixed bundle entries, no-overwrite, reading/exporting skill/schema without a database or configured credential, invalid run/snippet selection before storage, actual imported-request metadata/privacy and existing mode/conflict discovery. Skill-creator's standard validator passed the source artifact with PyYAML6.0.3 in an isolated task virtual environment. No independent agent or formal review was launched. Existing execution/credential/report fixtures were not repeated because their implementations were unchanged. Agent-host loading across all products, platform distribution and complete395-feature/release scope remain pending; exported instructions do not establish the remaining AI/enterprise/MCP features.

The agent workflow also exposed a missing CLI behavior: request-generation warnings were discarded. They now go to stderr while stdout/downloads remain pure source code. An actual saved-request Go generation fixture checks warning availability, clean source stdout and absence of saved auth/body values in diagnostics. This does not implement the warning's outstanding timeout/TLS/redirect mapping requirements.

## Private runtime variable inputs

`run --variables-file` / `--variables-env` compile bounded Serde JSON into existing private temporary pairs and local project/collection/environment updates. Input validation precedes temporary import or API execution; unknown fields, missing/malformed/oversized input and exclusive flags are rejected. Environment overlays require a selected/active profile. Native scope ordering, extraction/scripts, canonical immutability and redacted output remain shared with interactive execution.

Three actual process fixtures in `crates/cli/tests/variables.rs` passed invalid-input handling, scoped precedence/deletion and Dev/Production separation, and authenticated remote injection/privacy. The scope fixture compares canonical workspace exports before/after; the remote fixture compares saved workspace and checks stdout/report/history. The generated CI process fixture also passed injected headers and passing/failing fresh JUnit behavior. See [CLI.md](CLI.md) for the JSON envelope and [CI-PRESET-COVERAGE.md](CI-PRESET-COVERAGE.md) for secret references. This slice does not close remaining matrix/release work.
