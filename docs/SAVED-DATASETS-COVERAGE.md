# Reusable workspace datasets

WorkspaceData.datasets is an additive optional list. Named CSV/JSON sources are saved through existing authenticated document storage, workspace CAS/versioning and native/server synchronization. No new table or storage engine is used. Old workspaces default to an empty list. At most20 datasets and4 MiB aggregate original source are allowed, with existing per-source parsing limits. Source may be absent in redacted imports; execution then reports that data must be imported again.

The testing page manages dataset names, descriptions, privacy and original source, imports/previews with existing components, and explicitly saves changes through the common workspace save path. Collection runs select a saved dataset or temporary data. Saved mode passes dataset_id rather than copying data into the execution payload; the server resolves it from the owned canonical workspace. Dataset source editing is separate from running, while iteration count remains adjustable. Temporary and saved sources cannot be supplied together.

Default MoleAPI backups retain metadata but omit secret source; known credential copies are screened elsewhere in the workspace. Public sources are retained only when semantic/known-value screening leaves their parsed rows unchanged. Explicit include-secrets native backups retain exact CSV/JSON text and restore dataset objects. Other export formats reject saved datasets rather than silently discarding them. Sources are not fetched from external paths/URLs. Privacy markers govern backup masking, not encryption or a separate permission system; ownership remains at workspace level.

Evidence: old/missing-source compatibility and original text roundtrip; default hiding of secret/nested/copied values while safe public CSV is preserved; explicit native backup/import restoration; real owned API storage/CAS/conflict and dataset-ID execution against a loopback fixture; unchanged canonical data after runs; missing/ambiguous source rejection; native sync refusal when an old server drops datasets. Frontend fixtures validate-before-save and late-owner/unmount fences; typed source and existing preview/parser tests remain shared. Scoped Clippy/typecheck/production frontend checks passed, separate from platform/database publication checks.

Persistent query-backed/remote datasets, scenario graphs, schedules, report publishing and other full-product features remain unfinished. This change does not claim complete Apifox/Postman parity or a new release.
