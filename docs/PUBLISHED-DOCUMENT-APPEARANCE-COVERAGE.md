# Published document appearance coverage

Scope: `documentation-008` for immutable published Markdown snapshots. An owner selects light, dark or system theme, sidebar or top navigation, and an optional PNG logo for each new version. Existing publication rows deserialize to light/sidebar/no logo. A default create request retains its original idempotency digest; changed nondefault appearance conflicts on key reuse.

The server accepts at most 64 KiB of Base64-decoded PNG, limits dimensions to 512 × 512, rejects animation, decodes to bounded pixels and re-encodes without source metadata. It stores only sanitized bytes in the snapshot. The owner list reports theme, layout and logo presence without returning the logo. Locked public GET and failed unlock responses contain no appearance. The anonymous page uses the snapshot alone, renders the logo as a PNG data URL, follows live system color changes, and keeps search and navigation usable in both layouts.

Local evidence on the development worktree: the published-document route suite passed four cases, including sanitized source metadata, changed-key conflict, invalid PNG and oversized dimensions, old/default behavior, revocation and password lock. Independent review found that an invalid replacement file could preserve a previous logo or leave Publish disabled, and that PNG trailing chunks were not fully checked. Both paths now have regression cases: invalid replacement cancels the old read and clears the previous logo; the server validates through IEND and rejects missing/corrupt IEND and trailing bytes. The database integration suite passed its two cases with the new cross-instance appearance assertions on locally configured SQLite; PostgreSQL and MySQL were not configured locally. After the review fixes, strict server all-target Clippy, the embedded server build, 428 frontend cases across 114 files, and the 46-chunk production build passed. The previously rebuilt embedded server was exercised in a real browser at 390 px: dark/top anonymous page, data-URL logo, article switching, Chinese/English labels, search, no external images and no horizontal overflow. The system-theme password version stayed light with no title/logo before unlock, switched to dark on a dark reader setting after unlock, relocked on reload, and followed a later light/dark media change. Anonymous axe WCAG A/AA found zero violations and zero incomplete checks. The English owner form selected dark/top and a local PNG, published through its confirmation dialog, reported the appearance summary and stayed within 390 px. The Chinese owner form displayed all new controls at the same width without overflow. A rebuilt-browser recheck before the review fixes confirmed both successful publish and explicit Clear logo leave the native file input empty. A transient owner axe result while the confirmation dialog was closing reflected that active modal; the settled owner screen had zero violations, with contrast checks incomplete on existing pseudo-element backgrounds.
